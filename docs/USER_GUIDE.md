# 共感娃娃使用指南（v2.3）

电脑服务为 Bridge v2.6，开发板固件为 v2.3。支持无需电脑 USB 的 [Wi-Fi 采集](WIFI_CONNECTION.md)；主动推送与自建 AI 接入见 [主动互动指南](PROACTIVE_INTERACTION.md)，本机页面为 <http://127.0.0.1:8768/bridge>，演示回执不是模型回复。

## 日常启动

1. ESP32-C3 接通电源。已有 Wi-Fi 时灯慢闪尝试连接，成功后常亮。
2. 无线配对后运行 `tools/start_companion.ps1 -DeviceHost 192.168.1.50`（实际 IP 以设备为准），或复用已保存方式运行 `tools/start_companion.ps1`。USB 方式用 `-Transport usb -Port COM3`。电脑服务需运行，长期历史和互动会话由它保存。
3. 打开 <http://127.0.0.1:8768/companion>，设置每个通道的类型、部位、驱动和参数，设置人设，查询历史或模拟测试。
4. AI 客户端安装通用 MCP 后即可查询；安装步骤见 [AI_INSTALL.md](AI_INSTALL.md)。用户自行选择模型平台，无需在设备填入模型 API Key。

## 第一次配网或更换网络

- 无配置时灯快闪，出现无密码热点 `AI-Doll-33e864`（其他设备末尾编号不同）。
- 连接热点，系统可能自动弹出配置页；未弹出时手动访问 <http://192.168.4.1/>。
- 扫描周围 Wi-Fi，选择 2.4 GHz 网络，输入密码并保存。成功后配置热点关闭，灯常亮。
- 已有配置但 60 秒内连接失败，也会进入配网热点。
- 运行中长按 **BOOT 约 3 秒**重新配网。**RST** 只重启，保留 Wi-Fi 和部位名称。不要按住 BOOT 上电或复位，以免进入下载模式。
- 联网后从电脑连接页 <http://127.0.0.1:8768/> 或路由器设备列表取得 IP，打开设备设置页。IP 由路由器分配，建议保留 DHCP 地址；电脑需要与设备网络互通。无线配对和独立供电步骤见 [无线指南](WIFI_CONNECTION.md)。

## 灯的含义

| 指示灯 | 含义 |
|---|---|
| 快闪 | 正在提供无密码配网热点 |
| 慢闪 | 正在尝试连接 Wi-Fi，最多 60 秒 |
| 常亮 | Wi-Fi 已连接 |

通过 MCP 手动测试灯时会覆盖网络指示 3 秒，随后恢复。

## 反馈偏好与连接自检

在电脑 `/bridge` 页面设置称呼、希望避免的词句、反馈语气、时间参数和安静时段，保存会更新当前订阅。安静时段仍保留历史，结束后不补发期间的旧动作。点击“检查连接”可检查设备与采集服务；再让所选 AI 调用 `get_installation_status` 确认工具可调用。客观动作摘要及实际客户端限制见 [互动优化指南](INTERACTION_OBSERVATIONS.md)。

## 通道设置、历史与模拟测试

默认保留 CH0～CH7 的压力配置。在“通道配置”里，每路可选择压力输入、温度输入或震动输出，填写对应部位、选择驱动和端口，按需修改高级参数后保存。点击“添加通道”可增加逻辑通道，最多 16 路；允许删除和使用不连续编号。类型、部位和参数保存在 ESP32，重启保留；旧日志保留当时的名称和类型。

先用 `simulation` 驱动测试，不需要额外传感器：压力输入为 0～4095，按压 5 秒后自动释放，也可手动释放；温度输入为摄氏度；震动输出设置强度和时长，最长 5 秒，到时自动停止。模拟记录明确标记为 simulation，不代表实物读数或电机运动。

真实输入和输出开关独立。默认手动模式，重启关闭真实输入；确认接线后可保存日常模式，在重启后恢复输入。完整通道配置变更取消日常模式并关闭输入和输出。输出始终不自动恢复。压力校准及曲线操作见 [校准与日常模式](CALIBRATION_AND_DAILY_MODE.md)。接好传感器再打开真实输入。温度预设是 NTC 10k/B3950 分压采样，不能直接用于 DS18B20/DHT 等数字探头；现有 4051 只有八个物理输入。震动必须使用外置 MOSFET／驱动模块及必要的续流保护，不能将电机直接接 GPIO 或 4051；确认接线后再启用真实输出。详细引脚、温度参数和扩展限制见 [多传感器指南](SENSOR_CHANNELS.md)。

历史可以按类型筛选压力、温度和震动记录。温度显示 °C；无效 ADC 显示故障而非虚构温度。震动记录表示下发的输出指令，没有电机运动反馈。设备网页提供近期 RAM 日志，电脑页面提供持久历史。

普通模式下输入和输出事件持续归档，不要求 AI 立即回应。用户说“查询今天的互动”时，AI 查询混合设备历史并结合已设置人设回答。用户说“我要和你互动啦”时开启互动会话，只处理该会话中新发生的事件，结束后恢复普通归档。定期温度采样和输出命令不会一直延长会话的空闲期限。

MCP 无法单独唤醒空闲聊天；实时回应需要 AI 客户端在互动期间持续调用等待工具。FSR 提供受压数据，拥抱、轻摸等含义由 AI 结合部位、时序和聊天推断。

## 烧录与安装代码

现有开发电脑可执行：

```powershell
.\tools\build_lab.ps1 -Upload -Port COM3
```

烧录前关闭采集服务，再次启动后历史数据库仍保留。脚本优先使用项目 `.venv`，其次使用现有开发环境，最后使用 PATH 中的 Python；需要该 Python 已安装 PlatformIO。

换一台电脑时，可将代码包解压到英文路径，例如 `C:\AI_Doll`，使用 Python 3.12：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-companion.txt
.\.venv\Scripts\python.exe -m pip install platformio
.\.venv\Scripts\python.exe -m platformio run -d firmware -e supermini-lab -t upload --upload-port COM3
.\tools\start_companion.ps1 -Port COM3
.\.venv\Scripts\python.exe tools/install_companion_mcp.py
```

固件 bin 是应用分区镜像，首次整机烧录请使用上述 PlatformIO 上传，它会处理引导程序和分区表。

## 常见问题

- 页面打不开：确认电脑服务运行。USB 模式检查串口；Wi-Fi 模式检查设备独立供电、IP 与局域网互通。
- 串口不可用：关闭其他串口监视器、烧录程序，确认设备当前 COM 编号。
- 设备网页超时：电脑与设备需在同一可互通局域网，以 USB 页显示的当前 IP 为准。
- `SSE stream not offered; use POST`：直接打开 `/mcp` 会得到这个提示；它是工具调用端点，设置页应打开设备根地址 `/`。长期历史建议安装本机 STDIO MCP。
- 拔掉 USB 后离线：确认服务已切换 Wi-Fi，且设备有其他电源。仅拔掉唯一电源会关机。无线可继续保存电脑历史，但设备离线 RAM 缓存有限，断电清空尚未采集的数据。
- 升级后 AI 仍只看到旧工具：在 AI 客户端重新连接 MCP，刷新工具列表。本机 STDIO 应有 35 个工具；开发板 HTTP 应有 22 个工具。新事件端点是电脑的 `/bridge/mcp`，不是开发板的 `/mcp`。
- 新增通道没有真实读数：逻辑通道数量不是实际端口数量；检查驱动、物理绑定、通道启用和真实输入开关。不能给多个通道重复绑定同一个端口。
- 温度或震动没有硬件：选择 simulation 即可测试。当前实测未验证真实温度探头及电机驱动。

分享代码使用 `tools/package_companion.py` 生成的发布包；不要分享 `build/device-lab`，其中包含访问密钥和个人互动历史。
