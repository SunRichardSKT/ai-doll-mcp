# 断网后记录如何补传

> 按本页步骤操作即可；无需读完开发者资料。 [全部目录](../README.md)


设备最多缓存 **256 条事件**。按下 / 释放各占一条，温度和输出日志共同使用容量。这是断线缓冲，不是无限日志库。

电脑暂时关闭或网络断开时，娃娃会等待补传。它需要持续供电且真实输入已开启；缓存满会覆盖最早记录，所以不适合长期代替电脑历史库。

## 你需要做什么

正常供电并启用已确认的真实输入，电脑或直传服务器恢复后会自动补传、去重和确认。未接传感器的裸板不会自己生成真实压力。

在离线记录状态查看待补传、覆盖、损坏和写入失败数量。补完后待补传应为 0，累计容量覆盖不会归零。`get_event_storage_status` 为只读检查，确认 / 校时由主采集器负责。

旧事件只进入历史，不触发过时回复或重放电机命令。未知时间显示未知，不因刚收到就算作今天。

## 时间质量怎么看

设备联网并不代表已经校时。电脑采集服务会提供 UTC 时间；新启动首次采集立即校时，之后定期检查偏差，不依赖外网 NTP。

| 时间质量 | 含义 | 页面表现 |
|---|---|---|
| `device_clock` | 事件产生前，本次启动已由电脑校时 | 日期 + 设备时钟 |
| `estimated_from_boot_anchor` | 已知该次启动的时间锚点，使用运行时长估算 | 日期 + 估计时间 |
| `legacy_estimate` | 按接收时间估算的记录，不等同于精确发生时间 | 日期 + 估计时间 |
| `unknown` | 设备在电脑从未见过的一次启动中产生事件，未校时便重启 | 时间未知；不进入按日统计 |

时间取决于电脑时钟是否正确。未知时间不能仅凭“刚刚收到补传”恢复为实际发生时间。来自其他启动，或当前启动中已超过 5 秒的事件，标记为 `offline_replay`，仅进入历史；当前启动的及时事件仍能进入正常互动推送。补传不会延长当前互动会话的空闲计时。

开始互动时保存设备启动标识和最新事件序号。当前启动的新事件若因校时时延比会话开始时间早不到 2 秒，可依据序号边界归入会话，并标记 `session_time_quality=sequence_boundary`；原发生时间不修改。旧序号、旧启动和更大时间偏差不能使用此判断。

## 容量与丢失情况

256 条最多对应 128 次完整压力，混合记录会更少。缓存满覆盖最早事件并增加 `lost_records`。CRC 与临时文件提交用于检测异常，数据库提交后才 ACK，丢 ACK 重传会去重。

4MB 分区表不变，文件系统约 1.4MB；单条正文最多 1536 字节，256 条正文上限 384KiB，另有元数据开销。已有非空区挂载失败不自动格式化，报告不可用。损坏 / 未提交文件丢弃并计数，写入失败不算已持久保存。

高频事件增加 Flash 写入量。保持一个主消费通路，不让别的电脑抢先确认未归档事件；直传开启时电脑采集器停止消费。

## 通过与未验证

裸板模拟测试覆盖软件重启补传、256 条容量、270 条覆盖最早 14 条、未知时间与去重。未验证写入时物理拔电、Flash 人为损坏或满分区，不能承诺全部记录永不丢失。

开发测试见 [开发指南](../developers/DEVELOPER_GUIDE.md)，导出 / 删除见 [历史管理](HISTORY_MANAGEMENT.md)。


## 2.25预发布的手机同步与归档归属

仅手机模式新增独立的“自动同步记录”，与“触摸主动回复”分开。手机任务运行时先读取实时页，再小批补传；旧记录只归档，未知发生时间单独显示。新归档段与提交记录完成回读校验后才ACK，丢失ACK响应仅造成去重重读。

2.13固件提供90秒归档租约，主采集器约每30秒续租。手机、电脑和设备直传同一时刻仅一个主归档端可确认Flash；只读查询不取得清理权。切换路径先停止原归档端，或等待租约过期；设备重启租约失效，旧boot/epoch确认不能继续发送。

旧固件兼容复制不清缓存时，最多能反复读取当前最前24条持久记录，不能绕过ACK读取全部积压；实时RAM页另读。完整补传需要配套新固件。旧固件自身已开启的设备直传仍执行其旧逻辑，新手机不能据此接管。覆盖计数不直接等同于主归档端已经保存的数据丢失。

手机关闭或Operit被系统暂停期间不归档，恢复只能补设备仍保留的256条以内记录。需要长时间无人值守，请使用[服务器路线](../integrations/OPERIT_NO_PC.md#有自己的服务器)。本候选尚无目标手机锁屏与物理断电的新验收证据。
