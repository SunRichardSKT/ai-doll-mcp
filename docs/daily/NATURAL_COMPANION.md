# 触摸回应与自然陪伴

将触摸接进当前话题，选择需要回应的部位，并分别控制历史记录和主动回复。[教程目录](../README.md)

## 第一次设置

在支持 MCP 的聊天中说“打开娃娃的部位设置”，AI 调用 `get_settings_entry(section="body")` 返回设置入口。电脑页面在运行软件的电脑打开；家庭设备页需要局域网互通；热点页需先连接娃娃热点。服务器使用自己的管理连接。

电脑／服务器可设置部位名称、别名和回应偏好，例如“CH0 叫头顶，别名脑袋”“摸左脚时少回应一些”。部位名称写入设备，附加偏好保存在当前服务数据库。改名保留采样和校准，历史使用事件发生时的名称。

手机直连在 Operit“身体与传感器”在线修改名称与端口状态；人设来源、全局触摸回复和回应提示词保存在手机。电脑／服务器的别名、轻回应和安静时段在其管理页设置。各条路线使用自己的历史与偏好。

## 两个独立开关

| 设置 | 作用 |
| --- | --- |
| 自动同步记录 | 手机任务运行时采集并归档，默认开启 |
| 触摸主动回复 | 绑定聊天后按需开启，可选限时或常开 |

关闭主动回复可以继续同步；“停止后台任务”同时停止两者。Operit 常开通过后台任务续接，需允许 Android 后台运行。电脑／服务器的“轻回应”融入下一条普通聊天，“不回应”保留历史。

默认触摸反馈使用当前聊天人设，也可以在 Operit 选择娃娃人设。连续触摸合并成一批回应，释放用于更新持续时间。回应方式可在“人设与反馈”填写，例如“顺着话题，用一句温柔的话回应”。设置位置见[Operit 指南](../integrations/OPERIT_SETUP.md#自定义触摸回应)。

## 不同聊天客户端

| 客户端 | 互动方式 |
| --- | --- |
| Operit | 面板绑定聊天后开启触摸回复；模型生成期间继续采集并排队 |
| 普通 MCP 聊天 | 查询近期触摸，或开启 60 秒限时互动 |
| 支持事件订阅的宿主 | 按宿主能力配置主动订阅并核对目标聊天 |
| 自建聊天应用 | 接入事件桥，与原消息共用发送队列 |

普通聊天是否自动调用工具由宿主和模型决定。主动唤醒需要宿主事件接口，配置见[宿主接入](../integrations/HOST_INTEGRATIONS.md)与 [MCP Events](https://developers.openai.com/plugins/build/mcp-events)。

### MCP 调用顺序

为当前聊天保存独立、稳定的 `chat_id`。调用 `get_chat_context` 读取近期互动，在回应成功后按 `receipt_id` 调用 `acknowledge_chat_context`。`updates` 补充释放与持续时间；查询旧记录使用历史工具。

日常回复围绕话题和部位展开。原始 ADC 是采样值，单通道按压按实际触摸描述；测试时明确事件来自真实硬件还是模拟。

### 自建应用

使用 `DollBridgeClient.replyWithContext({generate, display, signal})`：生成回复、幂等保存到原消息列表，展示成功后确认。事件过期或静音时丢弃旧触摸上下文，设备服务暂不可达时继续普通聊天。完整流程见[原聊天开发指南](../developers/EXISTING_CHAT.md)。
