# 在原聊天中自然地陪伴

> 对应 2.24.1 预发布版；继续使用原聊天，不需要第二个模型。[教程目录](../README.md)

## 第一次设置

在原聊天说“打开娃娃的部位设置”，AI 调用 `get_settings_entry(section="body")` 返回链接。链接由你点击：电脑回环页面只在运行软件的电脑可用；设备局域网页需网络互通；192.168.4.1 需先连接设备热点；服务器页面继续使用已有管理连接。MCP 不会替你在远程服务器弹浏览器，也不会把管理权限变成公开权限。

电脑采集和服务器 MCP 可以设置部位名称、别名、回应方式和可选互动提示。例如“把 CH0 改成头顶，别名是脑袋”“摸左脚时少回应一些”。名称写入设备，其他偏好留在当前电脑或服务器数据库。普通改名不改采样、接线或校准；高级硬件设置仍在原页面操作。

同一个别名对应多个通道时，AI 应询问你具体指哪一路。电脑／服务器已经保存该设备配置时，设备离线也可保存服务端别名和回应方式；名称必须得到设备确认，超时需先核对，不会自动排队重试。历史仍使用发生时的名称。

Operit **仅手机直连**当前只支持在线修改部位名称及“关闭／模拟／已接入”。它不支持部位别名、轻回应、不回应或互动提示，也不支持离线保存端口修改；当前每路触摸按正常回应处理。手机人设和全局主动开关保存在手机插件目录，历史也与电脑／服务器分开。三条路线的设置不会自动互相同步。

## 两个独立开关

| 设置 | 默认 | 用法 |
| --- | --- | --- |
| 聊天融入 | 开启 | AI 实际调用工具后，可以将近期触摸接进正常回复。 |
| 触摸主动回应 | 关闭 | 开启后还需支持事件的宿主绑定当前聊天，使用有限订阅。 |

电脑／服务器的“轻回应”只融入下一条正常聊天，不单独主动发消息；“不回应”仍记录历史。默认 `persona_source=chat`，触摸反馈跟随当前聊天人设。用户在 Operit 明确选择“使用娃娃人设”后，`persona_source=doll` 仅让身体互动反馈采用保存的娃娃设定；模型、原话题和宿主聊天设置保持不变。连续触摸合并回应，释放不再单独说一次；默认关闭长按/连按摘要主动通知，已有高级偏好保留。

电脑／服务器 MCP 中可以说“回应简短一点”“关闭主动回应”“今天只记录，不回应”，让 AI 局部修改支持的偏好。Operit 也可通过面板关闭主动回应；仅手机模式关闭互动任务后不会持续采集新触摸，不能把它称为全天仅记录模式。日常无需报告 ADC、会话编号或倒计时；问设备状态、测试或查历史时才给具体信息。模拟来源始终说明，不能把压力原始读数当实际力度。

## 不同聊天客户端

普通 MCP 客户端：为本聊天生成并保存独立 `chat_id`；在正常回复前调用 `get_chat_context`。返回 `receipt_id` 的事件处理完后调用 `acknowledge_chat_context`；读取本身不消费，失败不要确认，游标和确认是不同概念。`updates` 为释放信息，不触发第二次主要回应。用户只查历史时使用原历史工具，不把旧历史当刚发生。

普通 Chat 是否每轮调用工具由宿主和模型决定，不能保证拦截所有用户消息。提示模板不能自行后台运行；不支持事件的宿主不会因开关开启就被唤醒。官方支持范围见 [MCP Events](https://developers.openai.com/plugins/build/mcp-events)，实际订阅和目标聊天反馈需另行验收。

自建应用：在原发送流程中使用 `DollBridgeClient.replyWithContext({generate, display, signal})`，与主动事件共用原聊天队列。`generate` 使用原模型及上下文，读取的 JSON 作为数据；`display` 幂等保存到原消息列表。成功展示后才确认；设备服务暂不可用时继续普通聊天。上下文在生成期间过期或静音时，丢弃带旧触摸的回答，最多重新生成一次普通回复。详细接入见 [原聊天开发指南](../developers/EXISTING_CHAT.md)。

确认仅表示客户端报告已处理，不证明任何平台真的显示了消息。主动订阅、服务器接收回执、真实模型生成和消息展示分别验证。
