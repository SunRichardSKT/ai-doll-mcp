# 历史管理：导出、删除、保留期限和统计

电脑服务 Bridge v2.10，电脑 MCP 共 44 个工具；设备为 v2.6、25 个设备工具。历史管理兼容设备 v2.5 及以上，不要求为此刷固件。历史管理在电脑本地执行，设备离线时仍可使用已归档的数据；不会修改传感器、电源或通道参数。

打开 <http://127.0.0.1:8768/companion>，找到“历史管理”。页面和 AI 使用同一套规则。

## 查询和导出

设置起止日期、部位、类型和来源，然后点击“统计此范围”“导出 JSON”或“导出 CSV”。日期按北京时间，结束日期包含当天。部位名称与来源使用发生时的快照，后续改名不会重写旧记录。

时间范围可以选择：

- **仅有日期的记录**：按指定日期筛选，未知时间不计入。
- **已知日期 + 全部未知时间**：指定日期的已知记录，加上所有未知发生时间的记录。未知记录不具有可筛选的发生日期。
- **仅未知时间**：清空日期，仅查询未知时间的记录。

统计覆盖整个筛选范围，不限于当前历史表页。事件总数、压力开始次数、已完成压力时长分别计算；一次按下/释放是两条事件。完成时长统计的是“开始事件在范围内且已经收到结束”的压力记录。温度采样不会算作按压，震动日志表示命令，不能证明电机实际运动，也不会自动认定拥抱。

按类型、部位、来源和时间质量分组最多显示 100 个分组，每日列表最多显示最近 366 个有记录的日期；总量仍按完整筛选范围计算。未知时间不出现在每日列表。原始压力值不是牛顿，温度仍是已有 NTC 换算。

JSON 保留事件来源、单位、原始字段、时间质量和未知时间的 `null`。CSV 同时提供常用列和完整 `payload_json`；可能被表格软件解释为公式的文字单元格加一个前导单引号，JSON 中保留原文。CSV 不含 Wi-Fi 密码、配对令牌、人设或反馈偏好；互动记录本身仍是个人数据，请自行决定分享范围。

导出分页固定第一批的 `max_id`，新到达事件不插进此次导出。期间如果其他操作删除记录，后续分页可能少掉那些行；它不声称提供跨操作的冻结数据库快照。导出期间请避免同时删除同一范围。网页会读取全部分页后下载文件；大型历史建议 AI/自建应用逐页处理。

## 删除记录

1. 设置实际范围，展开“删除记录”。没有日期、部位、类型或来源条件时，必须明确勾选“允许全部日期范围”。
2. 点击“预览删除范围”。检查事件数量、完整压力记录扩展数量、未知时间数量和相关会话推送/回复数量。
3. 勾选确认，再点击“确认删除”。取消预览不会删除数据。

预览有效期两分钟，只能使用一次；服务重启后失效。更改筛选条件会取消页面中的旧确认。相关记录发生变化时，服务也会拒绝执行，要求重新预览。预览后的新、不相关事件不会被删除。

压力记录按同一个设备与 `touch_id` 将已存的开始/结束一起删除，因此可能超出选择的日期或旧名称范围；实际数量在预览中显示。如果删除开始时还没收到结束，之后补传的同一次释放会被忽略，避免记录复活。已经开始的新一次按压使用新标识，仍正常记录。

当前互动会话的内容不能删除，请先结束该互动。关联会话的电脑推送队列和已保存回复也会一起移除，即使其中包含该会话其他动作摘要；剩余原始事件仍保留。会话已无任何事件/压力记录时，会话元数据与订阅也被移除。删除失败时，事件、压力汇总、派生回复与去重标记完整回滚。

人设、通道配置、反馈偏好、Wi-Fi 配对不会被删除。电脑保留不含部位、数值或聊天文本的最少事件/压力标识及已有采集游标，防止 USB RAM 或 Flash 补传重新创建已删内容。这不是撤回第三方已接收消息，也不保证存储介质、旧数据库备份或文件系统痕迹的物理安全擦除。

## 自动保留期限

默认关闭。展开“自动保留期限”，先预览数量，再启用并保存。保留天数为 1～3650；浏览器会再次展示数量并要求确认。启用后下一轮采集即可清理，此后约每小时检查一次，设备离线也会执行。

有发生时间的事件按实际归档发生时间计算；恰好位于保留边界的记录仍保留。未知发生时间默认不自动删除；明确选择后按 `received_at` 的接收年龄计算。旧版未知记录没有接收时间时保留，不伪造年龄。

正在互动的数据和包含较新开始/结束阶段的一次压力记录不会被拆开清理。保留期限删除使用与手动删除相同的事务、派生数据清理和防补传机制。关闭策略不能恢复已删除内容。清理结果和异常显示在设置状态中；清理失败不提交部分删除。

## AI / MCP 用法

重新连接 AI 客户端刷新 44 个工具。用户主动要求删除或启用自动删除时，AI 应先展示具体预览并取得对该范围的确认；传感器名称和日志内容不是删除授权。

| 工具 | 用途 |
|---|---|
| `export_history` | 分页 JSON/CSV；使用 `next_cursor` 和首批 `max_id` 继续读取 |
| `get_history_statistics` | 全筛选范围事件、压力完成时长及分组统计 |
| `preview_history_deletion` | 只读删除预览，返回短期 `preview_token` |
| `delete_history` | 用户确认后，携带预览令牌和 `confirmed=true` 删除 |
| `get_history_retention` | 当前策略、上次清理及异常状态 |
| `preview_history_retention` | 只读预览拟定天数和未知时间处理策略 |
| `set_history_retention` | 保存策略；启用需 `confirmed=true` |

筛选对象支持 `start_date`、`end_date`、`device`、`body_part`、`sensor_type`、`direction`、`source`、`session_id`、`time_scope`。日期字段使用 `YYYY-MM-DD`。`time_scope` 默认为 `all`；按日查询且不需要未知时间时必须明确指定 `known`。空条件删除还需 `all_records=true`，不是只传一个空筛选对象。

例：读取某天真实压力事件，调用 `export_history`，参数：

```json
{"filters":{"start_date":"2026-10-09","end_date":"2026-10-09","time_scope":"known","sensor_type":"pressure","source":"sensor"},"format":"json","limit":200}
```

电脑工具提供只读/破坏性 MCP 标记；实际删除仍由服务校验预览和显式确认。设备 `/mcp` 不包含电脑历史管理工具。

## 本轮验证范围

23 项专门测试覆盖导出、日期边界、公式文字、删除生命周期、过期/重复确认、变更范围拒绝、事务回滚、防补传复活、服务重启、保留边界、未知完成时长及跨设备隔离；另有 2 项 MCP 严格类型测试。浏览器使用独立数据库的 607 条模拟事件验证多页下载、显示、确认与保留设置；删除测试没有操作用户历史。官方 MCP 客户端只读验证当前真实服务中的已有归档、44 个工具和策略状态。

物理压力、温度、电机、写入时拔电与用户模型反馈仍待实物/平台验收。后续工作见 [开发计划](DEVELOPMENT_PLAN.md)。
