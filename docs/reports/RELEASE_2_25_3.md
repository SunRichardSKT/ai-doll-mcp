# 2.25.3 日常互动与维护修订

日期：2026-10-26，2026-10-27补充目标手机检查，2026-10-28补充并发返回修订。状态：本地候选，尚未发布。软件与 Operit 为2.25.3，交付镜像沿用2.13.3。本轮没有向用户设备烧录或修改电气参数；实测设备仍运行2.13.0。

## 已修改的行为

| 问题 | 修订后的行为 |
| --- | --- |
| 互动清理时文件写失败，监听标记一直占用 | 合并本地收尾保存，先记录已知回复结果；即使写失败仍尝试结束所属会话，并始终释放进程内监听标记。写失败仍明确报错，未确认发送不会自动重发。 |
| 一批待回应触摸中关闭一个端口，其他端口也被整批取消 | 按触摸逐条核对当前端口，保留同一批次中仍允许回应的触摸。继续使用原回执确认，不重复主要回应。 |
| 停止工作流时，第一项读取失败就跳过剩余任务 | 逐项尝试停止本安装所属的工作流，最后汇总未确认项；不修改其他安装的工作流，不把部分停止报告成全部成功。 |
| 新固件只改部位名称仍回写全部部位 | 支持`per_port_v1`时使用`set_channel_state`局部改名。旧固件保留名称专用兼容接口；阈值、校准、采样和其他通道不被替换。 |
| 手机补传已归档，同步数量仍只显示实时新增 | 同时累计实时页与补传页的新增记录，重复记录不重复计数。256条积压加1条新触摸的检查应报告257条。 |
| 打开历史与采集并发，旧读取可能覆盖刚提交的实时索引 | 历史读取复用归档器现有串行处理。归档与实时上下文均保留新触摸，不新增锁、队列或文件。 |
| 新触摸先被Flash页读到，随后RAM读取仍被去重为旧记录 | 仅在后续RAM读取符合当前启动、采集／会话边界、无缺口且30秒内时，保存同一事件的实时观察并及时唤回读取方。事件编号与首次收到时间不变，新增记录计数不重复增加；只有补传、过期、有缺口或会话前的数据保持历史。恢复时旧日检查点不能降级已提交的实时观察。 |
| 仅同步记录时，主动回复卡片显示同步任务的运行状态 | 主动回复卡片只使用互动任务状态；关闭反馈仍可独立同步，互动失败仍明确显示。 |
| 前台查询与后台任务重叠，状态结果被送给另一个调用 | 公开工具直接返回原函数的Promise，由宿主绑定当前调用；移除await之后的环境`complete`回调。官方1.12.2运行代码可复现旧实现把状态送给聊天列表，修订后两个结果分别返回原调用，不新增调度层。 |
| 已确认回执重复保存完整触摸正文 | 回执保留编号、聊天、事件身份与确认状态；已确认的正文从回执副本移除。完整历史继续保存在归档，未确认回执保留正文。 |
| 归档器保留无调用方的整索引覆盖入口及原始文件方法导出 | 移除未使用的`saveIndex`及原始文件读写导出；保留实际使用的归档、查询、索引读取、局部更新与恢复读取方法。公开工具与文件格式不变。 |
| 手机历史将不存在的日期折算到其他日期 | 拒绝2月30日等无效日期。显式的无效游标或页大小不再被默认值覆盖；闰日与本地午夜边界保留。 |
| 中文输入法的全角日期横线导致查询失败，未知时间翻页丢失筛选 | 设置页查询前将全角横线转为标准横线并去掉首尾空格；日期合法性仍由原接口校验。翻页沿用当前结果的筛选，不读取尚未提交的输入框内容，未知时间记录不混入其他日期。 |
| 设置面板重复读取同一份设置 | 同次面板读取复用已取得的配置，不重复访问手机文件接口。 |
| Windows构建的Linux安装脚本含CRLF，不能依赖Windows环境的换行转换 | 安装器源文件保存为LF。构建先检查Linux载荷，拒绝含原始回车的脚本；新增LF约束、Bash语法及TAR内安装器一致性检查。 |

打包器复用现有共享版本模块，减少发布时重复修改版本字符串。没有增加项目运行依赖。开发环境补装了项目已声明的烧录依赖，以便运行隔离烧录检查；测试没有写入真实开发板。

## 验证

已用原生产模块和明确的Android／设备／模型替身复现上述队列、停止、日期和计数问题，再验证修复。慢模型用例覆盖第一次触摸后生成45秒、期间再按五次、一次合并回复、端口中途关闭、静音、到期、停止及部分ACK恢复。

手机归档的24个场景覆盖256条积压与实时输入交替读取、RAM／Flash去重、归档后ACK、写入失败、回执恢复、重启、旧固件复制模式及已确认回执精简。新增归档计数用例复现原先只报告1条的错误，修订后正确报告257条。并发历史用例通过暂停旧归档段读取及跨日检查点写入，复现“历史已保存但实时上下文漏读”，修订后两条历史与新触摸上下文均保留；10／100／250个既有批次后的追加读取开销仍为8／8／8次。Flash先到用例验证稳定身份、快速返回、重启恢复及旧日检查点合并，并覆盖过期、有缺口和会话前的数据不能提升为实时。

## 2026-10-27目标手机首轮

实际手机为Operit 1.12.2，原AI Doll工具包2.25.0已保留数据更新为2.25.3，包详情页确认新版本。安装前已私下备份原包与插件目录，现有连接、聊天绑定和历史保留；身份与原始证据不进入公共包。该次更新通过已授权ADB替换既有包文件并重开应用完成，不代表同名导入界面支持覆盖。

随后在目标手机走通普通用户的原生升级流程：停止任务，在包管理仅删除AI Doll包文件，再从下载目录导入新版。Operit提示导入成功，实际安装文件与候选包哈希相同；升级前后独立插件目录的63个文件逐字节一致。指南已纠正“不支持同名覆盖却要求直接替换”的步骤。

设备运行2.13.0，实际MCP SDK发现30个设备工具，已读取端口、校准、数值与归档状态。租约可用，物理输出关闭，没有烧录。8路启用是配置状态，本轮只记录用户实际操作的CH0。

手机进入面板后自动显示在线，一键检查通过且未要求发送诊断。仅同步任务运行时，独立SDK与手机记录到相同的12条CH0开始／释放事件，来源为真实传感器且质量有效，原有256条历史保留。历史页实际打开并显示50条记录。上述结果不等同于慢模型或锁屏主动回复验收。

这轮真实采集暴露Flash先到的竞态：一条新按压约1.7秒内已归档，却被保留为离线补传，后续实时读取不能进入上下文。已据此补充回归并修订，修订后目标手机复验继续单独记录，不以替身检查冒充实际聊天结果。

修订包通过原生导入后，再次记录到6次CH0按压及释放，共12条事件。独立SDK与手机序列完全一致，12条均保留实时质量，6次按压均有已确认回执，发送队列最终为空；MAIN发送接口返回了匹配原聊天的非空回复。随后在原聊天屏幕实际看到自然摸头回复，原模型、人设与聊天保留。该轮不能证明五次按压全部发生在第一次思考期间。测试后端口配置和压力校准与测试前逐项相同，物理输出仍关闭。

第二轮实际识别4次按压，第一条生成期间，另外3次按压进入持久队列。第一条MAIN请求超过90秒等待时限，任务保留未确认发送并继续独立同步，没有自动重发；用户随后报告已收到迟到回复。用户确认不等于宿主自动回执；本轮尚未完成五次触摸合并送达验收。第二轮电脑SDK重新连接超时，手机同步仍成功，因此这轮新增事件只记为手机采集证据。

USB充电条件下观察到约4.7分钟连续锁屏，后台任务续接、会话到期重建及同步继续；解锁后该连续观察中断，不能写成30分钟锁屏通过，也不覆盖电池供电下的深度休眠。临时USB保持亮屏设置已恢复为原值0。

开启时面板曾显示笼统的“Error”，恢复独立同步时又短暂显示“尚未绑定”；实际配置、历史和聊天均保留。随后在官方1.12.2脚本运行代码中复现并发返回错位：旧实现的环境`complete`指向另一个尚未完成的调用。改为直接返回Promise后，并发状态与聊天列表分别回到原调用。全部工具包门禁通过；最后修订包已通过ADB替换安装文件并重开应用，随后手机断开，尚未完成此修订的目标手机界面复验。

用户已确认迟到回复，随后通过原生恢复页登记为已收到，未重发；待核对记录和队列已清空，并曾恢复仅同步。为安装最后的并发返回修订，再次停止了后台任务；该次更新结束时手机同步尚需重新开启，后续恢复结果见下一节。

## 2026-10-28目标手机复验

Operit仍为1.12.2。手机已安装的候选与本地工具包哈希一致，状态自动检查、恢复独立同步、读取已有聊天列表及从采集任务接入陪伴均返回正确数据。原绑定保留，没有重发诊断；本轮操作没有再出现先前的“Error”或短暂“尚未绑定”。

设备仍为2.13.0。供电重启后安装身份不变，手机自动结束旧启动的互动并续接，只处理新会话输入；端口配置、压力校准和物理输出关闭状态均与前次回读一致。本轮未烧录。

用户明确说明进行了多次按压。这次启动共归档72条CH0事件，为36组开始／释放；其中当前会话的14次有效按压分为2、7、5三批返回原聊天。实际观察到首条生成时7次事件排队，随后第二条生成时又有5次事件排队；三批均收到匹配原聊天的非空模型回复，14个按压身份各确认一次，队列最终为空。原聊天屏幕可见三条自然回应，继续原模型和人设，没有将释放另发为回复。会话边界前的记录只归档，不补发旧反馈。

独立电脑SDK的持续并行采样曾出现一次读取超时；随后按设备游标分页回读，72条事件的序号、通道、阶段、来源、质量、原始值、触摸身份和时长均与手机归档一致。该次超时保留为诊断观察，不声称原因已定位，也不把它解释为手机采集失败。

目标手机复现了中文输入法将日期横线转为全角而被格式校验拒绝；修订后同样输入能查询当天记录并显示标准日期。原生界面已打开历史，用户也确认可查看。官方1.12.2界面桥回归同时覆盖全角输入及未知时间记录翻页保持原筛选。更新前后378条已归档记录和聊天绑定逐项一致。最后的日期界面修订未改动互动引擎或硬件参数。

30分钟连续锁屏观察单独进行；其供电、调试连接及完成结果以本节后续补充为准，不沿用前次4.7分钟记录。

## 更新与使用边界

使用本地候选时，电脑／服务器与手机包采用同一批2.25.3文件，保留历史、插件数据、聊天绑定和校准。已运行正常2.13.3固件的设备不需要为这些软件修复再次烧录。仍需升级旧固件时，按实际能力和固定镜像清单处理，不根据手机版本推断。

当前公开下载仍使用[已发布的2.25.2](https://github.com/SunRichardSKT/ai-doll-mcp/releases/tag/v2.25.2)及该Release的固定校验文件；本地候选不能使用旧版清单校验，也不替换旧Release附件。

除上节明确记录的目标手机结果外，实际文件权限恢复与30分钟连续锁屏仍待验收。普通Chat空闲唤醒也没有因本次修复得到验证。其他硬件与宿主边界见[当前验证范围](VALIDATION.md)。
