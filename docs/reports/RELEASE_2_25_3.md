# 2.25.3 日常互动与维护修订

日期：2026-10-26。状态：本地候选，尚未发布。软件与 Operit 为2.25.3，固件沿用2.13.3。本轮没有向用户设备烧录或修改电气参数。

## 已修改的行为

| 问题 | 修订后的行为 |
| --- | --- |
| 互动清理时文件写失败，监听标记一直占用 | 合并本地收尾保存，先记录已知回复结果；即使写失败仍尝试结束所属会话，并始终释放进程内监听标记。写失败仍明确报错，未确认发送不会自动重发。 |
| 一批待回应触摸中关闭一个端口，其他端口也被整批取消 | 按触摸逐条核对当前端口，保留同一批次中仍允许回应的触摸。继续使用原回执确认，不重复主要回应。 |
| 停止工作流时，第一项读取失败就跳过剩余任务 | 逐项尝试停止本安装所属的工作流，最后汇总未确认项；不修改其他安装的工作流，不把部分停止报告成全部成功。 |
| 新固件只改部位名称仍回写全部部位 | 支持`per_port_v1`时使用`set_channel_state`局部改名。旧固件保留名称专用兼容接口；阈值、校准、采样和其他通道不被替换。 |
| 手机补传已归档，同步数量仍只显示实时新增 | 同时累计实时页与补传页的新增记录，重复记录不重复计数。256条积压加1条新触摸的检查应报告257条。 |
| 打开历史与采集并发，旧读取可能覆盖刚提交的实时索引 | 历史读取复用归档器现有串行处理。归档与实时上下文均保留新触摸，不新增锁、队列或文件。 |
| 已确认回执重复保存完整触摸正文 | 回执保留编号、聊天、事件身份与确认状态；已确认的正文从回执副本移除。完整历史继续保存在归档，未确认回执保留正文。 |
| 归档器保留无调用方的整索引覆盖入口及原始文件方法导出 | 移除未使用的`saveIndex`及原始文件读写导出；保留实际使用的归档、查询、索引读取、局部更新与恢复读取方法。公开工具与文件格式不变。 |
| 手机历史将不存在的日期折算到其他日期 | 拒绝2月30日等无效日期。显式的无效游标或页大小不再被默认值覆盖；闰日与本地午夜边界保留。 |
| 设置面板重复读取同一份设置 | 同次面板读取复用已取得的配置，不重复访问手机文件接口。 |
| Windows构建的Linux安装脚本含CRLF，不能依赖Windows环境的换行转换 | 安装器源文件保存为LF。构建先检查Linux载荷，拒绝含原始回车的脚本；新增LF约束、Bash语法及TAR内安装器一致性检查。 |

打包器复用现有共享版本模块，减少发布时重复修改版本字符串。没有增加项目运行依赖。开发环境补装了项目已声明的烧录依赖，以便运行隔离烧录检查；测试没有写入真实开发板。

## 验证

已用原生产模块和明确的Android／设备／模型替身复现上述队列、停止、日期和计数问题，再验证修复。慢模型用例覆盖第一次触摸后生成45秒、期间再按五次、一次合并回复、端口中途关闭、静音、到期、停止及部分ACK恢复。

手机归档的22个场景覆盖256条积压与实时输入交替读取、RAM／Flash去重、归档后ACK、写入失败、回执恢复、重启、旧固件复制模式及已确认回执精简。新增归档计数用例复现原先只报告1条的错误，修订后正确报告257条。并发历史用例通过暂停旧归档段读取及跨日检查点写入，复现“历史已保存但实时上下文漏读”，修订后两条历史与新触摸上下文均保留；10／100／250个既有批次后的追加读取开销仍为8／8／8次。

本机代理影响了一项本地HTTP测试；该测试现在明确直连隔离服务，不继承代理。开发环境原先缺少已声明的esptool，补齐后23项烧录检查通过。两者都不作为硬件故障或实板验收结果。

## 更新与使用边界

使用本地候选时，电脑／服务器与手机包采用同一批2.25.3文件，保留历史、插件数据、聊天绑定和校准。已运行正常2.13.3固件的设备不需要为这些软件修复再次烧录。仍需升级旧固件时，按实际能力和固定镜像清单处理，不根据手机版本推断。

当前公开下载仍使用[已发布的2.25.2](https://github.com/SunRichardSKT/ai-doll-mcp/releases/tag/v2.25.2)及该Release的固定校验文件；本地候选不能使用旧版清单校验，也不替换旧Release附件。

本候选尚未取得目标Operit、真实CH0慢模型排队、实际文件权限恢复与30分钟锁屏的新增证据。普通Chat空闲唤醒也没有因本次修复得到验证。其他硬件与宿主边界见[当前验证范围](VALIDATION.md)。
