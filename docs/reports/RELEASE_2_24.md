# 2.24：Operit 自动检查、完整触摸批次与历史页面

预发布交付，2026-10-21。Bridge 与手机工具包 2.24.0；继续使用已校验的 2.12.0 固件。[下载本版](https://github.com/SunRichardSKT/ai-doll-mcp/releases/tag/v2.24.0)。本轮没有烧录设备、调整电气参数或清除用户数据。GitHub 稳定版继续保留为 2.21.0，本版手机后台与新固件实板仍需验收。

本轮替换了 [2.23 的强制发送验证与触摸冷却处理](RELEASE_2_23.md)，旧报告保留当时范围。

## 使用变化

1. 进入面板先显示已保存的连接与缓存，再由原生页面加载回调自动检查在线状态。检查中、设备离线、连接不可达分开显示；不把尚未检查当作未配置。检查失败不改聊天绑定、不停止正在运行的陪伴。
2. 保存连接并绑定原聊天后即可开启陪伴。原聊天发送诊断与手动确认保留为可选排查，不再作为启动或续接门槛。实际发送结果不明确时仍保留记录，请核对该条反馈；不要求重新发测试消息。
3. 增加“触摸合并与等待”：默认松开后安静 1 秒再回应，可设置 0～30 秒，支持小数。0 为立即触发；等待期间的按压仍逐次保存。运行中也可修改，任务约 5 秒内读取新设置。
4. 历史使用独立页面，显示时间、部位、按下／松开及来源，可按日期查询、翻页。手机直连按日期读取已归档文件，设备离线也可查看；记录仍不自动删除。
5. 首页不再重复获取通道、人设和设置链接。完整概览包含这些信息时复用结果；没有新事件的手机轮询跳过每日历史读取，心跳按 5 秒保存，减少重复读写。

## “一次触发后又按五次”的处理

普通聊天的上下文仍保留原冷却策略；活动互动会话使用专用的批次快照读取方式。每次收取一页原始事件后，以该页游标为边界一次获取有效触摸，避免逐个查询及二次冷却过滤。五次独立按压不会因为间隔较短而被当作同一次删除。

读取、游标、队列和回执由一个任务顺序保存；模型生成期间继续读取设备。同一聊天最多一个模型发送任务，完成后将队列中的多次触摸合成下一条反馈，并提供完整次数、事件标识和释放时长。默认大于零的等待时间从松开／最后一次有效输入后计算，不在按住期间提前触发。

连续模式到达本段时间边界时，若模型仍在生成，会继续收集输入，等待该次完成后交给下一段；未发送队列保留在同一有效会话内。收到停止、静音、会话到期或队列有效期届满则取消尚未提交的反馈。新触摸仍需及时在 30 秒内采集，已捕获队列最多保留 120 秒；原始历史不因反馈取消而删除。

回执逐个确认并保存进度。已返回模型结果但确认中断时续做剩余确认，不重新生成，也不从已清理的旧回执重新开始。不能把模型返回或回执确认称为已验证用户看到了消息。

## 接口与兼容

- `get_chat_context` 增加可选 `session_id` 与 `through`。前者必须属于当前聊天且仍有效，后者限定本页最大事件编号；不传时原调用行为保持兼容。
- 返回 `context_protocol=leased-batch-v1`，用于明确判断服务端是否支持完整批次。电脑／服务器路径需要手机包和服务端一起更新到 2.24，并重启服务；仅更新手机包时会提示所需更新，不会默默退回丢触摸的旧策略。
- 手机直连的上下文由工具包实现，只更新手机包即可使用本次功能。固件无需为本次软件修改重新烧录。
- 逐事件历史补充稳定的启动标识与事件标识，解决电脑／服务器路径的释放记录无法匹配队列按压的问题。STDIO 52、HTTP status/history/interaction 2/9/19 的工具数量不变；只读配置不增加写入工具。

## 本机验证与实测边界

- 实际队列模块配设备／模型替身：首次触发后生成 45 秒，期间快速按五次；第二条包含完整五个独立事件及释放时长，没有并行模型发送。
- 自定义 3 秒等待后，六次连续触摸完整合并；另覆盖到期、停止、静音、任务边界续接和确认中断恢复。
- 实际手机适配器配设备接口替身：原普通聊天冷却仍有效，活动会话完整读取五次快速按压；十二条按下与释放仍在历史中。155 条每日归档支持离线按日期查询与翻页。
- Operit 1.12.2 实际 JS 界面桥配原生工具替身：加载回调刷新、重渲染不循环请求、无需发送测试即可开启、独立历史页面、保存 2.5 秒等待。
- 安装的 MCP SDK 对电脑 HTTP 与 Linux 直传服务执行真实协议调用，设备上传与模型明确使用替身。手机包元数据、公共包哈希、文档链接及私密文件排除另行检查。

上述检查不能代替用户安卓设备上的原生渲染、真实按压队列、模型表现及锁屏后台表现。本轮不新增这些实测结论。异步工具接口依据 [Operit 官方脚本指南](https://github.com/AAswordman/Operit/blob/main/docs/SCRIPT_DEV_GUIDE.md)，版本特定 JS 桥另使用本机缓存的 1.12.2 源码检查。

已回读 1.12.2 的原生实现：根节点 `onLoad` 每次打开页面实例只派发一次，因此使用宿主生命周期刷新，移除额外的重渲染防抖兼容分支。[对应源码](https://github.com/AAswordman/Operit/blob/dbf71916fae9750cfdc9f9a774f5a0fee56633fb/app/src/main/java/com/ai/assistance/operit/ui/common/composedsl/ToolPkgComposeDslScreen.kt#L1483)。`read_file_full` 原生实现读取完整文本，本轮没有凭猜测更换手机历史文件格式。

本机结果：SDK、协议、核心与元数据组合 44 项通过；SQL边界最终另复核15项通过；手机包构建门槛中的8组Node检查通过。完整包与文件校验结果随交付清单保存。已知失败和后续修复均保留在本机日志，不能把本机替身结果当作安卓实测。
