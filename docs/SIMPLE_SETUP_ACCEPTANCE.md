## 隔离 Linux 的实际链路

1. 未信任内部 CA 时 TLS 拒绝；显式信任后证书链、域名与安装身份校验通过。
2. 真实 ESP32 经 Wi-Fi / TLS 上传模拟事件，容器 SQLite 保存，物理输出关闭。
3. 重启、停止 / 启动、重复安装和版本更新后管理连接、设备绑定及历史保留。
4. 停本项目时无关容器继续运行；系统重启后 Docker 与服务自动恢复。
5. 实测后恢复开发板原电脑采集配置。

应用约 22MiB、Caddy 约 17MiB，仅为低负载样本，不是固定资源保证。本机证据在 `build/portable-acceptance/` 和 `build/linux-deploy-test/`，不进入公共包。

## 尚未在公网验证

用户没有实际公网服务器与域名，本次使用项目专用 DNS / 内部 CA / TCP 转发环境，生产模板未关闭证书校验。不能把这次成功当成跨公网网络、云安全组或 ACME 公网证书签发成功。

生产入口只有验证实际可信证书和本安装管理接口后才报告成功。设备直传与普通 Chat MCP 分别验收；模拟上传不证明实体传感器或空闲唤醒。完整边界见 [验证汇总](https://github.com/SunRichardSKT/ai-doll-mcp/blob/main/docs/VALIDATION.md)。
