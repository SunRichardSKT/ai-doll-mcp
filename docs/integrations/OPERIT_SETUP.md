# Operit：一次配置，在原聊天中互动

本页的电脑入口继续兼容。用户已确认原 Operit 能回应触摸；2.20 新增的 **服务器与仅安卓手机** 用法见 [免电脑操作指南](OPERIT_NO_PC.md)，两种用法都使用同一个工具包。手机新部署路径和锁屏表现需分别验收。

2.19.2 同时修正设置面板的工具名称回退。旧版出现 `org.ai_doll.companion:list_chats` 找不到工具时，重新下载并替换单个 ToolPkg，关闭旧面板后重开；保留已保存的插件数据和连接文件。

2.19.3 修正工作流回读兼容：遇到“AI Doll 工作流结构不完整”，替换最新同名工具包，关闭旧面板后重开，再点“一键检查”。会保留连接、聊天绑定和发送记录；只修复当前安装拥有的工作流，无需手动添加节点。

## 首次使用

1. 完整解压 `AI_Doll_Code_v2.20.0.zip`，保留根目录 `python`、`src`、`tools`、`clients` 和 `delivery`。双击 `AI_Doll.cmd`，打开“Operit 手机陪伴”。不需要另装 Python。
2. 手机和电脑接同一个 Wi-Fi。选择“模拟演示”或“真实设备”，网络列表只有一项时自动选择；多项时选手机可访问的电脑地址，再点“保存并启动”。模拟数据库独立保存，不会切换或修改真实硬件。
3. 页面点击“下载手机工具包”和“导出手机连接”，将两个文件传到手机。工具包只有一个：`AI_Doll_Operit.toolpkg`；连接文件为这台电脑生成，不在公共包中预填。
4. 在 Operit 的包管理中导入 `.toolpkg`。打开工具箱里的“AI Doll · 连接与互动”，点“导入服务器／电脑连接”，选择刚传来的 JSON。
5. 点“选择已有聊天”，选择标题，再点确认绑定。无需查找或填写聊天 ID。插件自动创建自己的状态文件；如 Android 提示，授予必要文件访问权限。
6. 点“一键检查”。插件检查已有聊天、MCP、状态文件，并自动生成本插件的两个工作流。不要手动添加节点、触发器或工具参数。

Operit 本身需已能在这个聊天里正常回复，继续使用你的原模型、角色和上下文。本项目不提供模型密钥、不新增娃娃账号、不创建聊天页面。APK 获取见 [Operit 官方发布页](https://github.com/AAswordman/Operit/releases)。

## 先验证后台发送

1. 在手机 AI Doll 面板点“原聊天发送自检”，返回已绑定的原聊天。
2. 任务由 Android 的一次性计划独立启动，可能延迟；控制按钮只报告“已安排”，不把它说成已监听。超过 90 秒仍未启动的任务失效，不补发。
3. 应看到一条带唯一编号的自检输入和 AI 回复。看到了再返回面板点“我已看到自检输入和回复”。这记录用户确认，不冒充宿主显示回执。
4. 没看到则点“查看状态”，核对任务错误。超时不会自动重试；先查看原聊天，再选择“确认已收到”“确认未发送”或“放弃本次反馈”。

本轮代码针对 **Operit 1.12.2 ToolPkg / Workflow / MAIN Chat 接口**，已使用该版本的 JS 实现修正导入、路由和工作流回读。用户随后报告原聊天已能回应触摸；该反馈不能替代新增服务器／手机直连路径、慢模型和锁屏场景的验收。旧版超时记录保留供排查。

## 60 秒互动

自检确认后，可直接在手机面板点击“开启触摸回应”，保存主动回应和聊天融入偏好，然后点“开始互动 · 60 秒”。模拟演示会产生一组明确标记的模拟摸头事件；真实设备需要实际按压已接通道。成功后可选择 15 分钟陪伴，不自动永久续开。

仅接 CH0 时只验收 CH0。同一次按压只主要回应一次，释放用于更新时长；不会解释成已测得的实际力度或拥抱。点击“停止互动”取消未开始的任务，并结束本插件拥有的服务端会话。已提交给原模型的回复可能仍完成，当前宿主接口不提供与用户普通生成队列分离的可靠撤回证明。

用户确认后台自检只绑定当前聊天和连接。改绑聊天或更换设备／服务器后重新自检，不能复用另一个聊天的确认。同一手机直连设备仅 DHCP 地址变化时保留绑定。当前提供 60 秒测试与 15 分钟陪伴，不承诺无限后台常驻、锁屏及时唤醒或自动绕过 Android 省电限制。

## 日常启动与停止

- 电脑双击 `AI_Doll.cmd`，复用保存的 Operit 设置；手机面板点开始。电脑与服务需要保持运行。
- 手机点“停止互动”结束本次互动；电脑的“停止手机连接”只停止本项目的 Operit MCP 进程，保留历史和配对。
- 电脑 IP 改变后，在管理页重新选择并导出连接；不会承诺跨任意网络自动发现。
- 电脑管理页 `127.0.0.1:8769` 只在电脑上打开。手机导入的是可达的局域网 MCP 地址，不是管理网页地址。
- 本地防火墙或访客网络阻断时，先核对同一 Wi-Fi 与可信网络权限。安装器不会自动扩大管理页访问范围。

## 从旧原型升级

关闭旧独立脚本监听窗口，在 Operit 停止旧手工作流。解压新版到新的目录时，先停止旧版服务，再保留并迁移原 `build` 数据目录；不要同时运行两份采集器。覆盖安装时先退出本项目服务和管理中心，不删除 `build`。

旧手机文件不会被删除。如果旧触摸发送状态尚未核对，在新面板绑定相同聊天和连接后，使用“升级：选择旧发送记录（可选）”选择旧 JSON。只有聊天和地址完全匹配且新版没有记录时才导入，未知发送继续阻止自动重发。导入的不是旧聊天账号，也不会自动执行旧记录中的其他内容。首次安装无需这一步。

旧 `0.1.x` 包和 [原型教程](OPERIT_PROTOTYPE.md)仅用于回溯。新版默认路径为单个 ToolPkg 与一次连接文件导入，不要混用两个版本的工作流。

## 开发与验证

手机源码在 `clients/operit/`；运行 `python tools/package_operit.py` 从当前允许清单生成工具包，不依赖历史 ZIP。电脑从 `tools/operit_service.py` 统一管理。

本机检查、实际 APK、真实传感器和目标聊天回复分别记录，见 [2.19 交付记录](../reports/RELEASE_2_19.md)。陪伴、事件策略、压力摘要和历史核心已迁到 `src/ai_doll/core/`，旧 `tools` 导入保留兼容；硬件与管理适配器的进一步整理不影响现有 MCP 名称及 Linux 服务。
