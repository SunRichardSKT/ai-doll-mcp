## 只有安卓手机：首次配对

前提是开发板已安装本项目固件并供电；本轮不提供安卓 USB 烧录。将本地候选 `AI_Doll_Operit.toolpkg` 传到手机并在 Operit 包管理中替换／导入，打开工具箱里的“AI Doll · 连接与互动”：

1. 点击“添加娃娃”，在系统 Wi-Fi 设置连接设备热点，回到 Operit 点“读取热点设备”。
2. 点击“打开热点设置，配置家庭 Wi-Fi”，填写家庭 2.4 GHz Wi-Fi。返回向导，点“配网后重新读取家庭地址”；已有家庭网络配置时可跳过重新填写。
3. 手机切回与设备互通的家庭 Wi-Fi，点“已切回家庭 Wi-Fi，完成配对”。核对安装身份和认证成功后才保存；失败不覆盖原连接。
4. 回首页点“选择原聊天”，按标题选择并确认。需要触摸反馈时开启“触摸主动回复”，无需发送聊天测试。

热点读取受登录、网络路由或目标 Operit 限制时，可在设备设置页取得连接文件、连接码或临时显示的二维码。面板“设备与连接”支持“导入连接文件”“核对并导入连接码”“拍照／相册读取连接二维码”。**不需要在 PCB、设备或外壳贴二维码**；单手机优先热点读取或文件导入，图片识别在手机本地完成。相机／相册及 WebView 往返需要目标 Operit 实测，无桥能力时保留文件和连接码入口。

仅手机模式首页独立显示“历史同步”，默认开启“自动同步记录”。不绑定聊天也可同步；绑定聊天只用于触摸主动回复。完整操作、登录保护和恢复限制见 [免电脑指南](OPERIT_NO_PC.md)。

## 电脑采集：首次使用

1. 完整解压本地候选 `AI_Doll_Code_v2.25.0.zip`，保留根目录 `python`、`src`、`tools`、`clients` 和 `delivery`。双击 `AI_Doll.cmd`，打开“Operit 手机陪伴”。不需要另装 Python。
2. 手机和电脑接同一个 Wi-Fi。默认使用已安装的真实主板和传感器。网络列表只有一项时自动选择；多项时选手机可访问的**电脑 IP**，再点“保存并启动”。模拟演示仅在开发者选项中使用，独立保存数据，不修改真实硬件。
3. 页面点击“下载手机工具包”和“导出手机连接”，将两个文件传到手机。工具包只有一个：`AI_Doll_Operit.toolpkg`；连接文件为这台电脑生成，不在公共包中预填。
4. 在 Operit 的包管理中导入 `.toolpkg`。打开工具箱里的“AI Doll · 连接与互动”，点“导入服务器／电脑连接”，选择刚传来的 JSON。
5. 打开“设置 → 对话窗口绑定”，点“选择已有聊天”，选择标题，再点确认绑定。无需查找或填写聊天 ID。插件自动创建自己的状态文件；如 Android 提示，授予必要文件访问权限。
6. 点“一键检查”。插件检查已有聊天、MCP、状态文件，并自动生成本插件的两个工作流。不要手动添加节点、触发器或工具参数。

Operit 本身需已能在这个聊天里正常回复，继续使用你的原模型、角色和上下文。本项目不提供模型密钥、不新增娃娃账号、不创建聊天页面。APK 获取见 [Operit 官方发布页](https://github.com/AAswordman/Operit/releases)。

## 自动检查与可选诊断

保存连接并绑定原聊天后，直接回陪伴首页开启“触摸主动回复”。进入面板会自动检查连接，不向聊天发送消息，也不要求点击“我已收到”。首页先显示已保存的信息，连接检查中不会误报尚未配置。

需要排查消息发送时，点“发送诊断消息（可选）”。它由独立后台任务发送，可能受安卓调度延迟影响；看到自检输入与回复后可以记录确认，但未做诊断、诊断超时或未确认都不作为日常陪伴的门槛。已有诊断任务运行时可用顶部“停止后台任务”结束。

实际触摸发送结果不明确时，先核对原聊天，再使用恢复按钮处理该条反馈；不自动重发，不需要重新运行诊断。

本轮代码针对 **Operit 1.12.2 ToolPkg / Workflow / MAIN Chat 接口**，已使用该版本的 JS 实现修正导入、路由和工作流回读。用户随后报告原聊天已能回应触摸；该反馈不能替代新增服务器／手机直连路径、慢模型和锁屏场景的验收。旧版超时记录保留供排查。

## 陪伴首页与常开

保存连接并绑定聊天后，回到“陪伴”首页，选择陪伴方式，再开启“触摸主动回复”。首次可选1分钟测试，验证后选择“常开，直到我关闭”；也保留15分钟限时模式。开关默认关闭。任务安排成功后返回原聊天，按压实际接入的传感器。

常开会自动续接有限后台任务和服务端会话，直到关闭。手机休眠、网络或系统停止Operit会中断，状态区区分“常开已启用”和实际任务；周期恢复可能延迟，不补发过期触摸。修改陪伴方式或聊天前先关闭开关。

仅接 CH0 时只验收 CH0。同一次按压只主要回应一次，释放用于更新时长，不解释成实际力度或拥抱。关闭主动开关结束本聊天互动和主动续接；仅手机模式若“自动同步记录”仍开启，则继续同步归档。已经提交给原模型的回复可能仍完成。发送结果不明时继续发送暂停，先核对原聊天再到“测试与帮助”恢复，不能自动重发。

发送诊断的用户确认仅作为排查记录；改绑聊天或更换设备／服务器不强制发送测试。同一电脑或同一手机直连设备仅DHCP地址变化时保留绑定。常开不是对Android全天后台、锁屏及时唤醒或绕过省电限制的保证。

## 思考期间的触摸排队

2.24会完整收集上一条 AI 回复期间的独立按压，不再把冷却时间内的不同按压直接过滤。例如第一次触发后，思考期间又按了五次，下一条反馈会收到这五次的完整数据，并合并为一条自然回应。

在“触摸合并与等待”中设置停止按压后等待多久，默认1秒，可设0～30秒并支持小数。大于0时先等松开，再等待没有新按压的相应时间；0为立即触发。运行中可修改，约5秒内使用新值。每次按压和释放仍保存到历史，合并的是回复。

有效新事件仍需在30秒内采集；已捕获触摸最多排队120秒，结束、静音和到期取消未发送反馈。常开任务续接保留同一有效会话的队列；不会把未知发送自动重试。

电脑／服务器用户升级时同时安装本地候选 2.25.0 服务端和手机包，再重启本项目服务；批次接口至少需要 2.24 服务端。只换手机包而服务端过旧时会明确提示不支持新接口。手机直连更新工具包后可使用旧固件的复制归档；需要完整分页和自动 ACK 时，另按固件指南更新至具有归档租约能力的配套版本。不要仅凭手机版本判断开发板已升级。

暗色和亮色页面均跟随Operit主题；卡片、文字和说明使用配套主题颜色。

## 分类设置

提示“请先停止当前后台任务”时，点击面板上方始终显示的**停止后台任务**，再修改连接、聊天或时长。它停止自检、互动、手机记录同步及其自动续接；旧包也可在 Operit 聊天中明确调用 `ai_doll_companion:stop`。停止本机任务不依赖远端在线；清理远端会话未确认时单独提示，不用“stopping”永久锁住设置。已有发送结果待核对时仍保留记录，不能自动重发。停止后要恢复独立同步，在首页重新开启“自动同步记录”。

| 页面 | 日常操作 |
| --- | --- |
| 身体与传感器 | 查看含关闭通道在内的端口；单独设置部位、关闭／已接入；可打开设备设置 |
| 人设与反馈 | 默认跟随当前聊天，也可填写并使用娃娃人设；切换不改原模型和聊天配置 |
| 对话窗口绑定 | 按标题选原聊天；发送诊断和确认均为可选 |
| 设备与连接 | 添加娃娃／热点找回地址、连接文件／码／二维码、手机直连、修正电脑 IP、查看已确认设备 IP 与设置网页 |
| 测试与帮助 | 试摸一下、一键检查、发送核对；真实输入测试不发聊天、不改阈值 |
| 开发者选项 | 默认关闭；模拟入口、实时数值、配置和后台任务诊断 |

端口三态需要固件2.11的`per_port_v1`支持。端口状态由设备内核保存，已接入不代表自动检测出物理插头；FSR松开可能同样接近零。普通操作不再使用“日常模式”。改一个部位或状态不更改校准和其他端口。参见[校准与端口状态](../daily/CALIBRATION_AND_DAILY_MODE.md)。

手机面板目前只编辑部位名称和端口状态。电脑／服务器的别名、轻回应和互动提示由其管理设置或 MCP 修改；**仅手机直连暂不支持这些部位偏好，也不支持离线保存端口修改或自动安静时段**。三种路线的能力与存储位置见 [免电脑指南](OPERIT_NO_PC.md#设置能力与离线边界)。

## 查看互动记录

陪伴首页点“查看互动记录”进入独立页面，支持日期查询、按下／松开来源与翻页。手机直连默认展示近期索引，填写日期可读取已归档记录，离线也可查；不确定发生日期的旧记录点“查看时间未确认的记录”，不会归入收到补传的当天。电脑／服务器模式查询其数据库。记录读取失败时保留明确错误，不把失败显示为空历史。

## 自动同步与补传

仅手机模式在首页“历史同步”中开关“自动同步记录”，或点击“立即同步记录”；这里显示最后同步、待补传、主归档端和缓存覆盖提示。一个采集任务共用实时与补传，模型思考不阻塞记录采集，补传旧记录不触发聊天。关闭主动回复不停止记录同步；“停止后台任务”则全部停止。

新固件通过 90 秒有限租约协调手机、电脑与设备直传，持有者每 30 秒续租；手机每次最多读取 24 条持久记录，完成归档、读回校验和提交后才 ACK。其他采集端占用时等待其释放或到期，不抢清缓存。已开启设备直传时使用服务器连接，不同时以手机直连作为主归档端。

旧固件没有租约时只复制当前可读的最多 24 条持久记录，不自动 ACK；缓存不清理，因此不保证读到其后的全部积压。完整补传需要配套固件和采集端。设备 Flash 总上限 256 条，按下／释放各占一条；覆盖计数是设备缓存状态，不等同于手机已归档记录丢失。手机被关闭或系统暂停期间无法持续采集。细节见 [断网缓存](../daily/OFFLINE_RECORDS.md)。

## 日常启动与停止

- 电脑双击 `AI_Doll.cmd`，复用保存的 Operit 设置；手机面板点开始。电脑与服务需要保持运行。
- 手机关闭“触摸主动回复”结束互动与主动续接；仅手机模式的自动同步可继续。要全部停止，点“停止后台任务”。电脑的“停止手机连接”只停止本项目的 Operit MCP 进程，保留历史和配对。
- 电脑 IP 改变后，按下面的“电脑重启后地址变化”更新，不需要重新安装工具包或重新绑定聊天。
- 电脑管理页 `127.0.0.1:8769` 只在电脑上打开。手机导入的是可达的局域网 MCP 地址，不是管理网页地址。
- 本地防火墙或访客网络阻断时，先核对同一 Wi-Fi 与可信网络权限。安装器不会自动扩大管理页访问范围。

## 电脑重启后地址变化

选择手动更新 IP 作为默认处理办法，不需要设置静态 IP：

1. 电脑打开管理中心的“Operit 手机陪伴”，选择当前可用的电脑局域网地址，点“保存并启动”。程序只停止并重新启动本项目原来的 Operit 服务，保留历史和私密路径。
2. 手机打开“AI Doll · 连接与互动 → 设置 → 设备与连接”，在“电脑 IP（电脑重启后可修改）”填入该地址，点“检查并保存电脑 IP”。只填 IP，例如 `192.168.1.20`；不要填 `http://`、端口或设备 IP。
3. 检查成功才保存新地址，原端口、聊天绑定、后台自检确认和发送记录不变。未完成任务会停止，不会恢复旧触摸；之后按需重新开始互动。

新地址不可达时保留原连接。若有发送结果待核对，改 IP 也不会清除或自动重发；先到原聊天核对，再使用恢复按钮。若同时更换了电脑安装、重置了私密地址或换了服务器，重新导入连接文件并检查连接和聊天绑定。发送聊天诊断仍为可选，不是重新开启的门槛。

**电脑 IP** 用于手机连接电脑 MCP 服务；**设备 IP** 用于访问 ESP32 设置页或手机直连，两者不能互换。管理中心 `127.0.0.1:8769` 仅供本机使用；设备热点地址 `192.168.4.1` 仅在连接设备热点时可用。家庭网络内的设备 IP 以设置页当前显示的可用地址为准。

## 仅手机模式：设备换 IP 或家庭网络

普通重启或 DHCP 换地址时，优先检查上次成功地址和固定 `.local` 名称，并核对安装身份；成功后只更新地址，保留聊天、回执和历史。前台一次恢复目标约 8 秒，实际受手机解析与网络影响；后台失败按 2、5、10、30、60 秒退避，“停止后台任务”后不再自动重试。

固定名称无法解析时，到“设备与连接 → 添加娃娃／从热点找回地址”，连接设备热点后重新读取。更换 SSID／密码时同时打开热点设置重新配网。手机网络切换由用户完成，不扫描整个子网，也不自动读取 Wi-Fi 密码。热点只作为配对／维护入口，不作为家庭地址长期保存。

同硬件重新烧录导致安装 ID 改变时需要重新配对；固定名称不能代替身份。旧历史保留，旧会话不复用。服务器路径则核对持久服务器实例和配对标识，设备家庭 IP 改变无需修改手机的服务器连接。

## 从旧原型升级

关闭旧独立脚本监听窗口，在 Operit 停止旧手工作流。解压新版到新的目录时，先停止旧版服务，再保留并迁移原 `build` 数据目录；不要同时运行两份采集器。覆盖安装时先退出本项目服务和管理中心，不删除 `build`。

旧手机文件不会被删除。如果旧触摸发送状态尚未核对，在新面板绑定相同聊天和连接后，使用“升级：选择旧发送记录（可选）”选择旧 JSON。只有聊天和地址完全匹配且新版没有记录时才导入，未知发送继续阻止自动重发。导入的不是旧聊天账号，也不会自动执行旧记录中的其他内容。首次安装无需这一步。

旧 `0.1.x` 包和 [原型教程](OPERIT_PROTOTYPE.md)仅用于回溯。新版默认路径为单个 ToolPkg 与一次连接文件导入，不要混用两个版本的工作流。

## 开发与验证

手机源码在 `clients/operit/`；运行 `python tools/package_operit.py` 从当前允许清单生成工具包，不依赖历史 ZIP。电脑从 `tools/operit_service.py` 统一管理。

本机检查、实际 APK、真实传感器和目标聊天回复分别记录，见 [2.19 交付记录](../reports/RELEASE_2_19.md)。陪伴、事件策略、压力摘要和历史核心已迁到 `src/ai_doll/core/`，旧 `tools` 导入保留兼容；硬件与管理适配器的进一步整理不影响现有 MCP 名称及 Linux 服务。

本版软件结果与目标环境待验收项目见 [2.25 候选记录](../reports/RELEASE_2_25.md)。拍照／相册、本地 WebView 解码往返、热点路由、真实 CH0 连续排队及至少 30 分钟锁屏需分别取得实际证据。技术依据：[ToolPkg 格式](https://github.com/AAswordman/Operit/blob/main/docs/TOOLPKG_FORMAT_GUIDE.md)、[Compose DSL 类型](https://github.com/AAswordman/Operit/blob/main/examples/types/compose-dsl.d.ts)、[工作流调度实现](https://github.com/AAswordman/Operit/blob/main/app/src/main/java/com/ai/assistance/operit/core/workflow/WorkflowScheduler.kt)。
