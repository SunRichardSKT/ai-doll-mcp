# 在原聊天中验证 MCP

> 按本页步骤操作即可；无需读完开发者资料。 [全部目录](../README.md)


先完成 [Windows 安装](../start/AI_INSTALL.md)与对应客户端连接。ChatGPT 普通 Chat 使用 [Secure MCP Tunnel](SECURE_MCP.md)，本机客户端使用生成的 STDIO 配置。

## 第一步：确认真的能调用

在已添加 AI Doll 连接的原聊天发送：

> 请实际调用 get_installation_status 和 doll_get_status，返回设备状态及两个 verification.call_id。没有工具就如实说明，不要用文档或旧结果代替调用。

返回的编号要与当前服务器的完成记录核对。STDIO 工具不一定提供同样的网关验证字段；有真实工具结果才算调用。插件 ZIP 上传成功、工具名称出现在说明里，都不证明服务已连通。

## 第二步：查询历史与配置

> 请读取通道、人设和反馈偏好，再查询今天的互动。区分模拟与真实来源，检查时间质量和最后同步状态，不把单通道按压直接解释为拥抱。

确认实际安装端口为“已接入”，对该传感器按住约 2 秒再松开，再查询历史。核对时间、通道、部位、数值、单位、`source=sensor` 以及开始和释放；只装 CH0 时只验收 CH0。历史来自电脑或服务器数据库，设备离线时仍可能查询成功。

## 第三步：60 秒互动

> 开始 60 秒互动。为本聊天保存独立 chat_id，调用 start_interaction(duration_sec=60)，保留返回的 session_id 和游标。每次最多等待 20 秒，只读取新事件。收到按压后结合原聊天和保存的人设回应；释放更新时长，避免重复主要反馈。到期或我说结束时停止。

等待开始后，按压并释放实际安装的传感器。服务器期限到期后结束；另一个聊天不能抢占当前会话。没有事件时不能编造反馈，也不能把历史当成本次新动作。使用模拟分支时，此步只对已选定的模拟端口注入新事件。

## 可选：没有传感器时做模拟测试

只有设备实际提供 `per_port_v1` 时使用本分支；旧固件按对应版本教程操作，不能把软件推算的端口状态当作已保存。

1. 在设备设置页或电脑管理中心“通道与校准”记录测试端口原来的状态和名称，优先选择一个未使用的压力输入端口，不关闭正在使用的真实传感器。
2. 只把这个端口改为“模拟”，点击“保存此端口”。不改驱动、阈值、校准或其他端口。
3. 核对电脑／服务器“人设与反馈”是否允许模拟来源。若此前禁止，先记录原值，本次明确允许后再测，结束恢复；历史中有模拟记录不代表它一定获准触发回复。展开“开发者选项 · 模拟与调试”的传感器窗口，选择刚才的端口，发送模拟按压并释放。非模拟端口的注入按钮禁用是正常行为，不用寻找旧全局输入开关。
4. 按上面的历史和 60 秒流程检查，结果必须保留 `source=simulation`，AI 反馈也简短说明模拟来源。
5. 结束会话后，把测试端口恢复为原状态并核对；原来关闭的端口恢复“关闭”。不清除历史或重置校准。

这一路用于电脑／服务器 MCP 的软件链路测试，不能证明实体 FSR、接线或物理输出正常。Operit 仅手机直连默认不接受模拟触摸反馈，当前面板也不提供该策略编辑；其验收使用真实已接入传感器，不把本分支当作手机全天主动回应的证明。

## 预期结果与限制

看到与本次来源一致的新事件及原 AI 的文字回复，才说明这次互动通过。真实按压与模拟测试分别记录，原始 ADC 或模拟值都不是实际力度；人设为空时不要编造“已保存的人设”。电脑／服务器采集保持运行时，结束后普通记录继续。

普通 Chat 的空闲主动唤醒未验证；本流程要求聊天在此次执行中继续调用等待工具。自己的应用可接事件回调，见 [主动互动](../developers/PROACTIVE_INTERACTION.md)。上传 ZIP 不会替你运行本机服务，见 [模板说明](../../templates/README.md)。

没有工具、SSE 提示或连接失败，按 [故障排查](../TROUBLESHOOTING.md)处理。当前验证范围见 [验证汇总](../reports/VALIDATION.md)。
