# Operit：服务器或仅安卓手机使用

本文对应 2.24.1 预发布版，修订安装与操作说明，保留 2.24 引入的自动连接检查、可选发送诊断、完整触摸批次和独立历史页面。[本次更新与验证范围](../reports/RELEASE_2_24_1.md)。

[下载 2.24.1 手机工具包与服务器包](https://github.com/SunRichardSKT/ai-doll-mcp/releases/tag/v2.24.1)。一个 `AI_Doll_Operit.toolpkg` 包含三种连接方式；已成功的电脑连接继续可用。用户已报告原 Operit 能回应触摸，新增的两种免电脑环境仍需分别在手机实测。仍用 2.21 稳定版时，按[稳定版校正版入口](../start/STABLE_2_21.md)操作。

| 用法 | 需要保持运行 | 记录位置 | 手机网络 |
| --- | --- | --- | --- |
| 服务器直传 | ESP32、服务器、Operit | 服务器 SQLite | 能访问服务器即可 |
| 仅安卓手机 | ESP32、Operit | 手机插件目录，分日 JSON | 与设备同一家庭局域网 |
| 原电脑连接 | ESP32、电脑服务、Operit | 电脑 SQLite | 能访问电脑地址 |

这两种免电脑用法都沿用原聊天、模型和人设，不需要第二份模型密钥或新建娃娃账号。仅手机模式不要求 Termux、Docker 或电脑中转。开发板需要已安装本项目固件并独立供电，例如 USB 充电器；本次不新增安卓 USB 烧录流程，也不需要为此重刷现有设备。

## 有自己的服务器

1. 从本版 Release 下载 `AI_Doll_Server_v2.24.1.tar.gz` 部署接收服务与 MCP，并使用同版手机包；升级保持原数据卷。首次安装见 [服务器安装](REMOTE_SERVER_SETUP.md)，也可将包上传服务器后从本地文件安装。
2. 在手机浏览器打开安装输出的管理链接，生成设备连接配置。
3. 手机给 ESP32 配好家庭 Wi-Fi，将服务器生成的配置粘贴进设备设置页“直连服务器”并保存。设备主动向 HTTPS 服务器上传，不需要家庭公网 IP 或路由器端口映射。
4. 等管理页显示设备在线，再下载“手机工具包”和该设备的“Operit 连接文件”。服务器必须配置手机可达的 HTTPS 地址，并启用 `interaction` MCP；仅状态或历史配置不能用于主动互动。
5. 在 Operit 导入工具包，打开“AI Doll · 连接与互动”，选择“使用服务器／电脑”，导入刚下载的连接文件。
6. 按下方共同流程绑定原聊天、检查和开始互动。

手机可以使用移动网络，设备继续使用家庭 Wi-Fi。服务器保存长期历史；手机断开时设备仍可上传，但手机关闭或 Operit 被系统暂停时不承诺继续生成原聊天回复。管理链接、设备配置和 Operit 连接用途不同，不能互换。

已有网站的服务器可将接收服务与 MCP 部署在同机，复用 HTTPS 代理；不要把服务器自身的 `127.0.0.1` 地址发给手机。高级部署见[项目服务接口](https://github.com/SunRichardSKT/ai-doll-mcp/blob/main/docs/developers/DIRECT_SERVER.md)。

## 只有安卓手机，没有电脑和服务器

1. 手机浏览器连接设备热点后访问 `http://192.168.4.1/`，为 ESP32 配置家庭 2.4 GHz Wi-Fi，并记下页面显示的家庭局域网 IP。也可在路由器已连接设备列表查看它。
2. 将手机切回能访问该设备的家庭 Wi-Fi。手机和设备不必连接相同频段，但不能被访客网络隔离；原 AI 聊天仍需要能访问它的模型服务。
3. 在 Operit 导入同一个工具包，打开面板，选择“仅用安卓手机”，填写设备家庭 IP，点击“连接家庭设备”。默认免登录时会自动取得连接信息，无需复制令牌。
4. 如果你主动开启了设备登录保护，在浏览器设备设置页取得 MCP 令牌，填进面板高级选项。连接成功会核对实际设备身份，不以旧报告中的编号为准。
5. 按下方共同流程开始。无需安装独立 MCP 服务，Operit 工具包内部直接读取 ESP32 的 HTTP MCP，并完成会话、历史与去重。

电脑采集或仅手机直连时，设备设置页的“直连服务器”应保持关闭。它只控制设备主动向接收服务器上传，不控制Operit的触摸主动回复。

手机不在家庭网络内时无法直连。需要在外使用时选择服务器方案；不要将设备管理网页映射公网。`192.168.4.1` 只有连接设备热点时有效，日常填写的是家庭 IP。设备2.12固件提供硬件派生的固定 `.local` 名称，手机连接后自动保存。旧IP不可达或被占用时，2.23工具包核对身份并尝试固定名称，成功后显示新的实际IP，保留绑定和历史。安卓或路由器不支持解析时，仍可手填设置页显示的当前IP；也可在路由器配置DHCP固定租约。旧固件需手动改IP，更新手机界面本身不要求烧录。

手机模式只在互动任务运行时采集；不会在手机关闭后补齐完整历史。每日已采集记录保存在插件目录的 `device_…_history_YYYYMMDD.json`，按 UTC 日期分文件，不自动删除；面板“查看互动记录”使用最多2000条的近期索引。该模式不读取或确认设备Flash补传队列。常规采集不修改硬件；用户在设置明确修改端口状态或部位时才调用设备局部更新，保留阈值。设备重启结束当前会话；常开任务在后续续接时重新建会话，只读取近期新事件。

## 设置能力与离线边界

| 功能 | 电脑／服务器连接 | 仅安卓手机直连 |
| --- | --- | --- |
| 部位名称、关闭／模拟／已接入 | 设备在线时修改并确认 | 设备在线时修改并确认 |
| 部位别名、轻回应、不回应、互动提示 | 通过服务端设置／MCP 保存；手机面板无这些编辑项 | 暂不支持，每路按正常回应处理 |
| 人设来源 | 可选跟随当前聊天或使用娃娃人设 | 同样可选，偏好保存在手机 |
| 自动安静时段 | 服务端反馈策略支持 | 暂不支持自动时段 |
| 离线修改部位偏好 | 已有设备配置时可存服务端别名等；改名不能声称已同步 | 不支持离线改端口或名称 |
| 离线查历史 | 电脑／服务器数据库已有记录 | 手机已经采集的近期索引和每日归档 |

手机关闭主动回应会停止互动任务；仅手机模式此时不会持续采集。三个连接方式的数据与偏好分别保存，不自动迁移或合并。按日期查询使用手机本地日期，适配器会读取对应的 UTC 日档并过滤，不需要用户手动换算文件日期。

## 两种用法的共同操作

1. “选择已有聊天”，按标题确认绑定，不用查聊天 ID。
2. “一键检查”，自动准备本安装拥有的工作流，不用手动添节点。
3. 保存连接并绑定聊天即可直接开启；面板自动检查连接。发送诊断消息和手动确认均可跳过，不作为日常门槛。
4. 在“陪伴”首页选择陪伴方式。首次用“1分钟测试”，之后可选择“常开，直到我关闭”，也保留15分钟。
5. 开启“触摸主动回复”，返回原聊天并按压实际安装的部位；2.24 会自动续接常开任务。Android调度可能延迟。
6. 关闭开关停止任务和主动偏好。已经提交给模型的回复可能仍完成，不能据此宣称撤回。改绑或更换连接前先关闭；电脑IP修正会停止常开，保留原绑定。

释放仅补充持续时间，不重复主要反馈；旧记录、故障值、过期事件不触发新回复，模拟来源继续标记。发送超时或结果不明时先核对原聊天，再选择恢复，不自动重发。

请允许 Operit 后台活动并按手机系统设置解除相应省电限制。前台转后台、锁屏和不同 APK 的长时间运行需实际验收，不能把一次触摸回复当成全天后台保证。普通 ChatGPT 的 MCP 调用与这个 Operit 脚本任务是两条不同通路。

## 验证顺序

每种模式分别检查：自动连接检查与设备身份 → 单次按下和释放 → AI思考期间再按五次 → 合并等待与完整记录 → 停止后不再发送 → 断网可停止 → 重连不重复旧事件 → 重开面板保留绑定与历史。服务器另测设备持续上传及 SQLite 历史；仅手机另测家庭 IP 变化、设备重启、离线查看已采集记录。

本机 SDK、模拟上传和 Android 替身结果见 [2.20 实施记录](https://github.com/SunRichardSKT/ai-doll-mcp/blob/main/docs/reports/RELEASE_2_20.md)；它们不能代替你的手机和真实传感器测试。

2.24的“触摸合并与等待”默认松开后1秒，可设0～30秒。服务器路径需要同步更新服务端和工具包；手机直连只更新工具包。历史已改为独立页面，手机可离线按日期读取每日归档。
