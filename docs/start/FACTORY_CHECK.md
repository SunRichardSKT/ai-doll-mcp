# 一代批量烧录与八路检测

[教程目录](../README.md) · [一代硬件](../../hardware/gen1/README.md)

下载 Release 附件 `AI_Doll_Factory_v0.1.5.zip` 并完整解压，在 Windows 双击 **AI_Doll_Factory.exe**。一次连接一块一代 ESP32-C3 主板。实时观察用于按压看变化，定值快检用于检查八路分压、错料和串扰。

## 出品操作

1. 用数据线连接 SuperMini USB 口，串口自动刷新；只有一块原生 USB C3 时自动选择，也可手选。关闭占用该串口的监视器与采集服务。
2. 选择随包固件、本地 ZIP、本地固件目录，或点击“从 GitHub 更新”。窗口显示校验后的来源、版本与八路采样支持情况。
3. 可填写设备名称。烧录时名称写入设备显示名和热点名，允许 1～32 个 UTF-8 字节，中文通常每字 3 字节；留空使用随机名称。批次／编号字段单独保存到本机记录。
4. 选择检测方式。已刷好的板可直接开始检测，烧录按钮会在写入后自动进入所选模式。默认烧录速度为 115200，连接稳定后可选 460800。
5. 实时观察可以同时按压多个传感器，查看各路的实时、最低和最高 ADC 值。点击“停止采样”保存观察记录。
6. 换下一块板，等待串口刷新，再次开始。每轮重新记录最低、最高值和检测结果。

烧录期间保持连接，必要时按住 BOOT、点按 RST、松开 BOOT。关闭忙碌窗口会请求结束任务，等待写入或下载完成后保存记录并关闭。

## 10 kΩ 定值快检

用一只实测接近 **10 kΩ** 的 1% 电阻做测试插头。把电阻跨接到 PA2.0 2P 插头的两个针脚，两处焊点分别绝缘。已制带线板可用其对应线束。[测试插头接法](SINGLE_CHANNEL_TEST.md#可选的-10kω-电阻定位夹具)

1. 只用 USB 供电，拔下 J1～J8 的传感器线。在工具中选择“10 kΩ 定值快检”，点击“开始定值快检”或“烧录并定值快检”。
2. 八路都空着时点击“记录本步”。任一空载口超过 **150 mV** 会判定未通过。
3. 把同一个测试插头依次移到 J1～J8，每次按提示点击“记录本步”。剩余七个口保持空载。
4. 每步取五帧毫伏读数的中位数。默认插入测试头的端口应为 **1240～1430 mV**，其余口应不高于 **150 mV**。八路完成后自动保存结果，拔下测试头即可换板。

在 3.30 V 供电下，4.7 kΩ 串联电阻对应约 **1336 mV**，误装 1 kΩ 时约 **1571 mV**。批量开始前用良品和万用表确认实测范围，必要时调整窗口中的通过上下限。定值快检验收主板接口和分压，传感器本身用实时观察另测。

## 固件来源和设备身份

本地 ZIP 需包含一套同目录的四镜像和 `FLASH_MANIFEST.json`，也可选择包含这五个文件的目录。复用项目烧录器校验芯片、地址、大小和 SHA-256。GitHub 更新从项目最新正式 Release 下载，额外核对发布包 `SHA256SUMS.txt`，下载并校验完成后选中，点击烧录按钮才写板。准备来源期间操作按钮锁定，下载或校验失败时保留先前选择。

普通烧录保留配网、端口状态、校准和历史，每次生成新内部设备编号。自定义名称作为显示名与热点名。批量工具的操作记录独立保存，设备身份以本次烧录回读为准。

实时观察需要固件提供 `factory_sample_revision=1`。定值快检还需要 `factory_sample_millivolts=true`，随包 0.1.5 固件已支持。窗口显示所选固件支持的模式，实时观察仍可使用兼容的旧固件。

随包固件具有一代日常功能和 USB 八路采样入口。该入口直接读物理 MUX 口，日常关闭的通道也可查看；日常使用按已保存的端口配置运行，新板默认只启用 CH0。实际装了其他通道时，应按接线设为“已接入”。

## 观察与记录

串口错误、重启、设备身份变化或无效采样会结束本轮并记录原因。中途停止定值快检会保留已测各路，整板标为“已停止”。

每次操作在程序旁 `build/factory-check/` 保存独立 JSON，并追加 Excel 可读的 **检测汇总.csv**。实时观察标为“已记录”。定值快检保存空载电压、各口实测、使用的限值和通过状态，异常口可在汇总表定位。历史记录沿用现有格式。

烧录日志在 `build/flash/`，下载缓存位于 `build/flash-sources/`。这些目录只保留在生产电脑。Excel 占用汇总表时，先关闭文件再保存新一轮记录。

单路无响应、固定高值或串扰时，按[单通道故障标准测试流程](SINGLE_CHANNEL_TEST.md)定位。电池／开关供电、充放电温升、Wi-Fi、NTC 和湿润片按各自功能另行验收。

## 维护与打包

复制程序时保留整个文件夹。根目录入口为 `AI_Doll_Factory.exe`，运行库和烧录辅助程序在 `_internal`，源码在“对应源码”。重新打包保留程序旁已有 `build/` 记录。

维护使用项目 `.venv` 或带 Tcl/Tk 的 Python，安装 `requirements-flash.txt` 后运行 `python tools/factory_check.py`。独立打包安装 `requirements-factory-build.txt`，再运行 `python tools/package_factory.py`。修改固件后先编译并导出镜像。要生成发布附件，运行 `python tools/package_factory.py --release-zip delivery/AI_Doll_Factory_v0.1.5.zip`，再通过 `python tools/package_companion.py --include-factory` 校验并写入交付清单。

开发回归运行 `python -m unittest discover -s tools -p test_factory_check.py`，固件来源测试见 `test_flash_sources.py`。替身采样仅验证程序逻辑，实体传感器按实物连接和观察记录验收。
