# 局域网无线升级

适用于当前交付的 ESP32-C3 SuperMini 固件。`doll_get_status` 可读取 `ota` 状态。升级是设备管理操作，需要用户选择本地文件并确认，不由传感器事件自动触发。

首次安装需要 USB 写入交付固件。之后设备独立供电，在同一可互通局域网内升级，无需电脑 USB 数据连接；日常日志仍由电脑采集服务保存。

## 设置页操作

1. 打开设备地址，例如 `http://192.168.1.50/`，登录账号 `admin`。管理密码可在设备设置页查看，也保存在已配对的本机私有配置中。
2. 找到“无线固件升级”。选择交付包 `firmware/prebuilt/firmware.bin` 和同目录的 `FLASH_MANIFEST.json`。
3. 点击“检查并安装固件”，核对版本并确认。保持稳定供电，不操作传感器或修改网络。
4. 上传和校验完成后设备重启。页面等待新启动确认，通常在重启约 30 秒后显示完成。如果设备 IP 改变，重新发现设备后打开新地址。

不要上传 bootloader、分区表、文件系统、合并烧录镜像或其他芯片的固件。配网期间的无密码热点不开放 OTA；需先联网并通过管理账号与设置令牌认证。固件清单不是数字签名，仅能检验传输完整性；使用可信来源的固件。当前管理链路是局域网 HTTP，不应映射到公网。

## 命令行操作

在项目根目录运行，替换实际设备 IP。`--config` 指向本机已经配对的私有配置，不应上传 GitHub。

```powershell
python tools/ota_device.py --host 192.168.1.50 --config build/device-lab/device-private.json --firmware firmware/prebuilt/firmware.bin --manifest firmware/prebuilt/FLASH_MANIFEST.json --confirm
```

工具在写入前验证目标型号、大小、SHA-256 和应用镜像头。不会下载远程文件或打印密码。写入请求失败不自动重试；提交响应丢失时，先查询设备版本和启动分区再决定下一步。

## 保存与恢复行为

- 只写入非当前运行的应用分区，保留现有分区表、NVS 网络/通道配置及 LittleFS 离线记录。电脑历史、人设和反馈偏好不随设备升级改动。
- 升级开始时停止震动并关闭输出许可；升级期间暂停触摸采样和模拟输入，不把这段空白当作传感器读数。正在按压或校准时拒绝开始升级，先释放或取消校准。原日常输入模式按配置在重启后恢复，输出始终不自动恢复。
- 每次最多传输 3072 字节，严格检查偏移。上传期间临时关闭 Wi-Fi 省电，结束或取消后恢复。30 秒未收到有效分块自动取消。完整长度、SHA-256 和 SDK 镜像校验全部成功后才切换启动分区。
- 新应用启动后至少运行 30 秒、完成足够主循环且有足够空闲内存，才确认启动。确认前重启时，由启用回滚的启动程序退回上一份有效应用。这个检查验证基本启动能力，不能发现所有业务故障或保证今后任意版本兼容。
- 上传过程中取消或断线不会切换启动分区；若提交已成功，取消无法撤销。不能开机或始终无法联网时，用 USB 恢复已知可用版本，不要全片擦除。传感器配置格式的未来迁移仍需保留向后兼容；回滚应用不会自动还原已经修改的用户数据。

状态字段包括运行分区、分区容量、已接收字节、待启动确认和最近错误。不公开上传票据或私有凭据。

验收范围见 [设备测试报告](DEVICE_LAB_TEST_REPORT.md)。裸板模拟测试不代表真实压力、温度或电机已经验收；升级写入时的实际掉电尚未强制测试。
