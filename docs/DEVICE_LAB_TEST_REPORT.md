## 当前对话接入

电脑 MCP 增加可选 `doll_chat_companion` 提示模板，官方 SDK 在真实 STDIO 连接中能列出并读取；45 个工具保持不变。适配器验证 ACK 后才展示、重复投递复用、取消后不生成/展示、生成失败恢复原界面忙碌状态。指引要求沿用当前对话的模型、人设与上下文。这批验证在 Bridge 2.12.2 执行，Wi-Fi 状态检查通过；独立聊天页面和模型配置接口均未提供。上述测试证明接口与控制流程，不代表任意官方聊天支持空闲唤醒，也不代表已验收真实 AI 反馈。

新增原聊天队列专项通过：普通回复→互动生成→ACK/异步写入→下一条普通回复顺序；取消等待任务、迟到生成丢弃、异步写入停止信号、等待期间续租、聊天隔离、容量限制与失败恢复。测试使用明确的回调替身，没有执行真实模型推理，也没有建立新聊天界面。

启动/结束专项通过：四个启动等待阶段取消、双击启动共用会话/监听、启动失败回滚、结束失败保留 ID 并阻止重新监听、旧流迟到 404 不关闭替换连接。另在真实本机采集服务验证双启动、创建订阅后延迟返回再取消、模拟取消订阅失败仍结束实际会话及重试清理。延迟和网络失败由测试明确注入，没有调用模型，没有删除用户历史；结束后无活跃会话，真实输入/输出关闭。

当前运行的本机工作对话完成真实 MCP 工具测试：通过 Wi-Fi 向 ESP32 注入头部模拟按压，读取新会话的压力开始/结束事件，ADC raw 为 1800，持续 5002ms，来源为 simulation、时钟质量为 device_clock、投递质量为 live；当前 AI 在同一对话中给出简短反馈。没有保存人设，沿用已有“温柔自然”反馈偏好。会话已结束，真实输入/输出维持关闭。最初测试的 120 秒会话在准备阶段空闲到期；改用 300 秒会话连续完成注入与读取后通过。

## 连接争用修复

Bridge 2.12.3 修复设备连接和同步锁的无限排队。隔离测试先复现旧代码在连接占用期间无法返回、释放连接后才发送控制命令；修复后，排队最多等待 2 秒，超时的操作没有开始，不在连接恢复后补发。状态诊断明确提示 busy；历史仍可读取已保存的数据；结束当前会话不要求设备同步成功。网页接口返回 503 / `device_busy`。

26 项针对性测试通过：8 项争用与 HTTP 接口测试、7 项归档/会话测试、11 项局域网传输测试。全部使用隔离数据库与明确的测试替身，不连接真实电机、不修改用户历史。2 秒只限制取得锁前的排队，网络传输仍使用其自身超时，不代表整次 MCP 调用必定在 2 秒内完成。

实际本机采集服务已升级为 2.12.3；升级前确认没有活跃互动，升级后核验配对与连接文件哈希保留、Wi-Fi 正常、真实输出关闭。当前 Work 再次实际调用 `get_installation_status` 和 `doll_get_status` 成功，工具仍为 45 个，采集错误为空。没有改固件、没有打开 USB 数据通道；这个检查仍不证明普通 Chat 或空闲唤醒成功。
