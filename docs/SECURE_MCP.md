# 在普通 Chat 中使用 AI Doll：Secure MCP Tunnel

更新日期：2026-10-10。使用原 ChatGPT 的模型、人设和上下文；电脑通过 Wi-Fi 采集 ESP32，历史保存在电脑 SQLite。这里的窗口只用于配置服务，不是新的聊天窗口。

## 第一次安装

1. 安装 Windows 64 位 Python 3.12 或更新版本，勾选加入 PATH。解压代码包到固定目录，避免之后移动运行目录。
2. 给 ESP32 供电并配网，电脑和设备连接可互通的局域网。在设备设置页启用 MCP，记下设备的局域网 IP 和配对令牌。设备操作见 [使用指南](USER_GUIDE.md)。
3. 双击 `tools/Install_Secure_MCP.cmd`。安装器创建项目自己的 Python 环境、安装固定版本依赖、下载并校验官方 Windows 隧道客户端。新安装会询问设备 IP 和配对令牌；已有配对会保留，不需要一直插 USB。
4. 在本机配置窗口点击“创建隧道”，在 [OpenAI Platform](https://platform.openai.com/settings/organization/tunnels) 创建自己的专用隧道，关联将使用的 ChatGPT 账号或工作区。填写 `tunnel_` 开头的编号。
5. 点击“创建运行密钥”，在 [API keys](https://platform.openai.com/settings/organization/api-keys) 创建运行密钥，需要 Tunnels **Read / Use** 权限。创建隧道需要 **Read / Manage**。填写运行密钥，点击“保存并启动”。不使用管理密钥，也不另接聊天模型 API。
6. 等待窗口显示本地工具发现通过和隧道成功连接。在 ChatGPT 的插件页面创建自定义 MCP，切换到“隧道”，填入同一个编号，选择无需身份验证，创建连接并添加到普通 Chat。

Platform 密钥连接的是 OpenAI 隧道控制服务，不是娃娃账号。ChatGPT 登录不能代替运行密钥。每位下载者使用自己的隧道和运行配置。权限及关联要求见 [官方隧道说明](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)，官方客户端见 [tunnel-client](https://github.com/openai/tunnel-client)。

## 日常操作

- **启动**：设备供电并联网，双击 `tools/Start_Secure_MCP.cmd`。已有采集器和隧道实例会复用；不重复开启。关闭配置窗口后服务继续运行。
- **查看状态**：打开配置窗口点击“检查状态”。同时检查进程、本地工具发现、官方客户端健康和最近成功的控制服务轮询。进程存在或 `/readyz` 成功不单独等于隧道已连接。
- **停止远程连接**：点击“停止连接”，或双击 `tools/Stop_Secure_MCP.cmd`。只停止本项目 Secure 隧道与专用网关，电脑历史采集器继续运行。其他隧道不受影响。
- **改工具范围**：选择范围并保存启动，然后在 ChatGPT 刷新连接的工具。`status` 为 2 个状态工具，`history` 为 9 个只读工具，`interaction` 为 13 个工具，增加开启、读取、查看和结束限时会话。
- **重置本地连接地址**：点击“重置连接地址”。旧网关路径立即失效，官方隧道重新指向新路径；ChatGPT 使用的隧道 ID 保持不变。这里不是重置 Platform 的 API 密钥。

配置文件在本机 `build/device-lab/secure-mcp/`，官方客户端缓存位于 `.tools/secure-mcp-tunnel/`。不能把本机运行目录当作给别人安装的模板。服务只监听回环地址，Secure 转发的目标是专用 MCP 网关，不是设备设置页或数据库文件。

## 按顺序验收原聊天

先发送：

> 请实际调用 get_installation_status 和 doll_get_status，返回设备状态及两个结果中的 verification.call_id。没有工具时如实说明，不用阅读文档代替调用。

两个编号应与本机 `gateway/calls.jsonl` 中已完成的记录匹配。`run_id` 用于识别当前服务实例。安装器的 SDK 调用不能代替这项目标 Chat 实测。可在项目根目录运行以下核对入口，替换两个 Chat 实际返回的编号：

```powershell
.\.venv\Scripts\python.exe tools/verify_chat_calls.py --installation-call-id <编号1> --device-call-id <编号2>
```

核对记录仅表示用户报告的两个状态调用与当前服务器匹配，不证明完整互动反馈或后台唤醒。

然后发送：

> 请读取通道、人设和反馈偏好，再查询今天的互动历史；明确区分模拟与真实记录，不把单通道按压直接解释为拥抱。

在本机设备设置页“模拟测试”产生一次按压，再查询历史，核对时间、通道、部位、数值、单位和来源。模拟功能留在本机界面，13 个远程工具中不开放模拟注入、配置写入或物理输出控制。

最后发送：

> 开始 60 秒互动测试，调用 start_interaction(duration_sec=60)，为本聊天保存独立 chat_id 和返回的 session_id。每次最多等待 20 秒，用游标只读取新事件。收到模拟按压后，结合原对话和保存的人设简短回应；释放只更新持续时间，避免重复主要反馈。到期或我说结束时停止。

等待开始后，再在本机界面模拟按压。没有事件时不能编造反馈；两个聊天同时测试时，后一个不能抢占前一个会话。服务器期限到期自动结束，结束后不能继续投递旧事件。查询历史可以在设备离线时返回电脑已存记录及同步状态；采集器必须运行才能持续同步。

普通 Chat 空闲时自动被触摸唤醒不属于当前保证。限时互动依赖聊天在执行期间继续调用等待工具；工具安装成功不能证明后台主动推送。使用云端 AI 查询的数据会发送给该平台。

## 连接失败如何判断

- **本地 MCP 未通过**：先看采集服务是否启动、配对是否完成、设备与电脑是否互通。历史服务可在设备暂时离线时工作，设备状态错误要单独显示。
- **客户端运行，隧道没有成功连接**：查看官方客户端的控制服务轮询。当前电脑采用网络代理时，安装器沿用其已配置的 HTTP/HTTPS 代理连接 OpenAI，回环 MCP 和局域网设备不经过代理；不修改系统代理设置。
- **HTTP 401 / 403**：检查运行密钥、Tunnels Read / Use 权限、所在 Platform 项目/组织和隧道的账号关联。
- **网络超时**：确认当前电脑能够访问 `api.openai.com`。客户端按官方退避机制重连，不因一次状态检查超时重复启动实例。
- **Chat 看不到工具**：确认已选择正确隧道并添加到当前对话，修改工具范围后刷新连接；查看本机真实请求记录，再区分关联、工具发现与工具执行问题。
- **端口被其他程序占用**：默认专用网关端口 8774。安装器不会停止或接管其他程序；可通过配置 API 选择空闲端口。

SDK、健康检查和目标 Chat 结果分别记录。当前阶段实测见 [验收报告](MCP_ACCEPTANCE_2_13.md)。Cloudflare 已通过的状态连接保留为备用；Secure 尚未通过的项目不能用 Cloudflare 的结果代替。
