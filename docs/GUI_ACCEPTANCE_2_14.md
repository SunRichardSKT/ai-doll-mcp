# 管理中心 2.14.0 验收

日期：2026-10-11。固件保持 2.7.0，MCP 工具名称和数量保持兼容。管理中心是本机安装与配置界面，AI 回复仍在原聊天。

## 方案与实现

采用浏览器 GUI + Python 标准库启动器，复用现有采集、MCP 生命周期、通道、历史与反馈模块。可行性高：不增加 Electron、Node 或前端构建依赖；依赖尚未安装时也可以打开引导。Python 64 位 3.12–3.14 是外部前提，缺少时显示安装说明。

GUI 自动完成项目环境、依赖、配置生成、设备验证保存、采集启停、官方隧道客户端准备和 Secure 管理。用户仍需给设备配网、复制设备令牌，并在官方页面完成隧道账号关联和 Chat 添加连接。这些账号操作没有用浏览器自动化代替。

统一侧栏覆盖安装、设备、通道/校准、人设/反馈、历史、模拟/读数、MCP、维护和使用说明。现有页面作为功能面板嵌入，复用一套控制逻辑。移除旧 Tk 隧道窗口与生产代码对开发缓存 SDK 的路径回退；旧 Secure 命令入口兼容打开管理中心。

## 已取得的证据

| 检查 | 结果 | 范围 |
|---|---|---|
| Python 回归 | 63 项通过 | GUI 引导/凭据传递/错误/任务互斥/本机 HTTP；Secure、HTTP 网关、私密路径、宿主转发；包含离线启动和停止时连接断开的回归 |
| 浏览器导航 | 通过 | 四步安装、STDIO 配置生成、原通道/人设/偏好/历史/模拟/维护面板、反馈子页往返；无脚本异常 |
| 响应式与截图 | 通过 | 1360、768、390 像素宽度，无整页横向溢出 |
| 独立解压首次安装 | 通过 | 无本机开发 SDK、无配对/密钥，实际通过 GUI HTTP 安装环境并生成配置 |
| 设备离线界面 | 通过 | 历史查询与统计可用，显示缓存通道的只读副本；不生成假读数 |
| GUI 实际服务操作 | 通过 | 通过界面停止本项目采集和 Secure，重新启动采集、网关与隧道客户端；本地 MCP 工具发现通过 |
| 固件升级入口 | 文件/门控回归通过 | 复用既有 OTA 镜像校验与上传；未确认/错误镜像不发送；本轮没有实际刷写 |

实际启停验收时设备不可达，隧道启动返回时尚未观察到连接成功；随后通过 GUI“检查状态”确认 `tunnel_connected=true`、13 个工具和本地 MCP 验证通过，设备仍为 `device_online=false`。这不作为新的物理验收或普通 Chat 验收。10 月 10 日目标 Chat 的状态、历史和模拟反馈证据继续保留在 [MCP 2.13 分阶段报告](MCP_ACCEPTANCE_2_13.md)。

独立解压包通过首次安装：GUI HTTP 入口创建全新 .venv、安装固定依赖、生成指向解压目录的 STDIO 配置；没有复制本机配对或隧道密钥。ZIP 完整性、逐文件 SHA-256 和公开允许清单校验通过。收尾移除旧隧道 UI、旧代码交付 ZIP，保留在用 CLI、回归测试及个人历史。私人截图、操作状态与证据在本机 `build/device-lab/gui-acceptance`，公开包只包含代码和报告。

## 未替代的验收

真实压力/温度/电机、OTA 写入时断电、全新电脑的实际局域网配对、Operit/OpenClaw，以及普通 Chat 空闲唤醒仍需要各自环境。GUI、SDK、本机进程存在不能代替这些结论。
