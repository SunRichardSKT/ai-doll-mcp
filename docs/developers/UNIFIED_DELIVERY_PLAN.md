# 统一代码、安装与日常使用规划

规划日期：2026-10-15；状态更新：2026-10-16。本文保留重构方案。统一 ToolPkg、管理页、工作流与四个共享策略核心已落地；用户报告原 Operit 已能回应触摸。2.20 增加服务器与仅手机路径，目标环境、长时间后台及其余适配器整理仍未完成，见 [当前记录](../reports/RELEASE_2_20.md)。历史失败记录保留，不因重新打包而改成已验收。

## 1. 当前问题与调整目标

当前 Operit 接入依次增加了查询、监听、独立诊断三个 JS 和两个电脑 CMD，用户需要手填 URL、对话 ID、文件路径、工作流确认字段和期限。增量包又要求用户判断覆盖目录和手机版本，导致一次验证变成多次配置。

下一版目标：按环境下载一个完整包；首次用向导完成连接和聊天绑定；日常只操作开始、停止、查看状态。继续使用原 AI 聊天、原模型和人设，不新增聊天产品，不要求娃娃账号，不重新烧录稳定固件。

重构不能自行解决尚未查明的 Operit 后台发送失败。真实手机原聊天收到一次可见的自检回复，是正式启用主动陪伴的门槛；协议测试或工作流完成状态不能代替。

## 2. 用户应当看到的流程

### 首次设置

1. 电脑解压完整 Windows 包，双击 `AI_Doll.cmd`。根目录自带 Python。
2. 在现有管理中心选择 Operit，选择真实设备或明确标记的模拟演示。沿用已验证的配对配置，多个可用网络时只需点选一次。
3. 管理中心导出一份手机连接文件；手机只导入一个 `AI_Doll_Operit.toolpkg`，在其设置中导入连接文件。二维码作为可选入口，必须先核对当前 APK 的实际支持，不以不存在的扫码接口作为默认依赖。
4. 手机点击“绑定当前对话”。读取宿主返回的当前 ID，并显示聊天标题让用户确认；无法识别时列出已有聊天供选择。禁止猜测、写固定 main 或静默改绑。
5. 首次按宿主要求授予必要文件权限，由插件管理状态文件。优先使用经当前 SDK 验证的应用私有存储；不能直接取得时，用一次目录选择授权，不要求手写 Android 路径。目录授权返回 content URI 时，必须通过实际支持它的接口访问，不能当成普通绝对路径拼接。
6. 向导运行分阶段检查，并生成属于本插件的工作流。用户只点开始，不画节点和连线。

### 日常使用

- 电脑打开 `AI_Doll.cmd`，复用已保存的网络、设备和服务配置。
- 手机使用“开始互动”“停止互动”“查看状态”。开始沿用已绑定的聊天，不自动跟随用户切换到其他聊天。
- 普通聊天融入默认开启，触摸主动回应默认关闭；已有用户偏好优先保留。主动开启是用户明确操作，不由导入插件或收到触摸自动开启。
- “模拟演示／真实设备”在同一设置页切换；设备离线时明确显示离线，不能自动改用模拟数据冒充在线。
- 开始控制调用应立即返回任务状态，监听任务在宿主允许的后台工作流运行。不得在原聊天 AI 的同一工具轮里等待并向自己递归发送。

## 3. 参数如何减少

| 当前需要填写 | 新版处理 | 用户需要做什么 |
| --- | --- | --- |
| 每次 MCP URL | 首次导入连接配置，之后读取已保存配置 | 导入一次 |
| chat_id | 读取当前对话或列出已有对话，保存绑定 | 确认聊天标题 |
| state_path | 插件选择、生成并管理状态文件 | 必要时首次选择目录授权 |
| workflow_confirmed | 改为内部调用约束和真实用户启动状态，不能把一个布尔值当安全授权 | 日常不填写 |
| 手动触发器和连线 | ToolPkg 模板／Workflow API 生成，创建后回读节点与连线 | 首次点击安装或修复 |
| duration_sec | 默认预设，测试 60 秒；日常提供少量时长按钮 | 可选，不手填数字 |
| 模型回复等待时间 | 内部按宿主能力管理，与新事件接收期限区分 | 高级设置才显示 |
| 诊断包、诊断 JSON | 同一工具包的“一键检查”和结果页面 | 点检查，必要时导出报告 |
| delivered／not_sent／discard | 转成“确认收到／确认未发送／放弃本次”恢复按钮 | 只在发送结果不明确时选择 |

首次可能仍需系统权限点击、连接文件导入和聊天选择；不宣称任何 Android 版本都能无权限、零操作安装。IP 变化后的恢复先做实际可用的连接检查；未实现手机发现前不承诺自动找到任何网络中的电脑。无需重复配置模型服务。

## 4. 代码职责重新划分

推荐目录：

```text
firmware/                 已验证的设备固件、驱动与预编译镜像
src/ai_doll/
  core/                   配置模型、事件策略、会话、投递状态与恢复
  devices/                USB、Wi-Fi、配对、发现、设备协议
  storage/                SQLite、配置读写、增量迁移
  mcp/                    STDIO、HTTP、Secure、工具兼容层
  service/                采集、设备直传、进程和任务生命周期
  management/             现有管理界面、安装向导、诊断与导出
clients/operit/
  manifest.json           一个 ToolPkg 的清单
  main.js                 注册入口
  packages/               连接、绑定、互动、恢复与诊断的内部模块
  ui/                     连接与设置面板，不创建新聊天界面
  workflows/              本插件拥有的工作流模板
tests/                    核心、协议、启动器、迁移和宿主适配检查
tools/                    构建、打包、开发维护与旧路径兼容包装
deploy/                   Linux 接收服务与 MCP 部署
docs/                     单一用户指南、开发文档和真实验收记录
```

先抽取共享代码，再迁移模块；不一次性推倒设备、数据库和全部接口。旧 `tools/` 的外部入口先做兼容包装，避免已配置的 STDIO 路径失效。构建临时目录不用于保存唯一的源码版本。

### 共享核心

统一配置校验、事件类型／部位／来源／质量、会话边界、冷却／合并、按聊天确认和错误码。电脑采集、Linux 直传、MCP 与手机适配器复用同一份协议定义，减少相互复制的策略。

保持多传感器扩展边界：压力、温度输入与震动输出分别描述能力；输出不作为用户触摸。用户已有校准、通道参数与名称不因目录或安装方式改变而重置。

### Operit 适配器

负责宿主版本和能力检查、聊天绑定、任务启动、原聊天发送、保存／展示证据及自身工作流维护。使用 ToolPkg 包装多个内部模块，用户只导入一个文件。原型的查询、监听和诊断不再分别要求安装。

工作流自动生成应使用真实宿主接口并回读验证。只更新本项目记录的 workflow ID，不改用户其他工作流；重复安装复用，不反复创建副本。旧版 APK 不支持时显示具体最低能力要求，不提示用户盲改 JSON。

### 管理与进程

统一电脑配置和入口，现有 `AI_Doll_Server.cmd`、烧录入口可保留为对应功能的兼容快捷方式。Operit 的两个测试 CMD 从默认用户入口收起，演示和真实设备在管理页选择。

启动复用已有本项目服务；停止只结束本项目拥有的进程。Windows 优先让很薄的 CMD 调用随包 Python，减少多层 PowerShell 包装；确实保留的中文 PowerShell 脚本继续验证 Windows PowerShell 5.1 编码和 Unicode 路径。

## 5. 配置、任务与发送恢复

电脑保存设备和服务配置，手机保存连接资料、绑定信息和自己的发送恢复状态。导入连接资料不导入电脑历史，不复制个人配置到公共工具包。

配置增加 schema_version 并做增量迁移；更新代码不覆盖数据库、校准、配对、聊天绑定和用户偏好。变更连接或聊天前展示目标，并处理该目标未确认的发送，不能清空旧 JSON 绕过未知结果。

投递状态至少区分：收到、排队、已提交宿主、取得回复、客户端已确认、过期、结果不明确。操作成功、API 返回、保存历史、屏幕展示分别记录，不能互相冒充。

新触摸接收期限、排队有效期、模型生成等待分别定义。宿主只有一个 timeout 参数时明确能力限制，不承诺已经独立控制所有阶段；不使用无限重试补偿未知发送结果。真正开始生成的回复与未发送的排队消息区别处理。

初版仍采用有限时长任务，不承诺锁屏、强制停止应用或系统杀进程后全天监听。日常状态应显示当前聊天、连接来源、任务期限和宿主支持情况，开发编号与参数折叠在高级页。

## 6. 一键检查如何呈现

管理中心和手机插件使用相同阶段名称：

1. 运行环境／插件版本。
2. 文件读写和已保存配置。
3. 手机到服务的连通性与实际 MCP 工具发现。
4. 原聊天 ID、标题与模型手动可用情况。
5. 经用户点击后发送可见自检消息，核对返回与历史。
6. 一次模拟触摸、释放去重、停止和过期。
7. 用户准备好后单独验收真实 CH0。

错误页面保留具体原因和最近检查结果，提供有针对性的重试／修复按钮。读取检查可以自动重试；有副作用的发送遇到未知结果应暂停。诊断默认不输出用户聊天正文、连接凭据或个人历史。

## 7. 交付方式

一个发布版本按环境提供完整制品，而不是让用户叠加补丁：

| 制品 | 用户操作 |
| --- | --- |
| Windows 完整 ZIP | 完整解压，根目录自带 Python，打开 AI_Doll.cmd |
| Linux 小型服务包／安装脚本 | 同一服务器部署接收和 MCP，不包含 Windows 运行环境 |
| AI_Doll_Operit.toolpkg | 手机导入一个包，内含设置、工作流和诊断 |
| PCB／BOM 资料 | 独立硬件资料，软件更新不改变已下单铜图形 |

软件各制品使用同一发布版本与协议兼容说明；固件保持独立版本，软件重构不要求重刷。下一版可使用新的统一版本号，只有实测通过后才发布，不提前把规划标为稳定版。

所有制品直接从当前源码和声明的允许清单构建，不再依赖某个旧 ZIP 作为源码或唯一文件清单。增量补丁只作为内部维护手段，默认下载页只展示清楚的完整版本。

旧原型脚本和 0.1.x 验收证据保留到开发资料，迁移完成前保持可回退，不继续作为新用户安装入口。公共包排除本机配置、数据库和凭据。

## 8. 实施顺序与通过条件

| 阶段 | 工作 | 通过条件 |
| --- | --- | --- |
| 1 | 收敛配置与绑定；定位实际 Operit 后台回复 | 一个入口能识别真实目标并得到一次原聊天自检回复；记录 APK 版本 |
| 2 | 一个 ToolPkg，整合设置、诊断和工作流安装 | 新手机无需分别导入多个 JS；不手填 ID、文件路径或节点参数 |
| 3 | 电脑统一入口与连接导出 | 免费局域网向导可用；复启沿用配置，手机只首次导入连接文件 |
| 4 | 抽取共享 Python 核心，迁移旧 tools 实现 | 旧 MCP 工具和外部脚本入口兼容，历史与校准保持 |
| 5 | 完整制品、更新与清理 | 全新解压可启动、旧安装升级保留数据、文档与制品一致 |
| 6 | 原聊天体验与宿主边界验收 | 新模拟触摸一次主要回应、自然结束、断网恢复、两聊天隔离；真实 CH0 单独记录 |

每阶段形成源码中的检查和同一套完整候选制品，不让用户重新拼装临时修复包。阻塞项显示在原设置页，等待 APK／权限／宿主实测时不转移到另一个模型或聊天产品。

ChatGPT Secure 和本机 STDIO 继续兼容。Windows 普通 Chat 的外置事件入口后续复用共享核心，主动能力按实际宿主验证，不因此次 Operit 结构重构就宣称支持。

## 9. 技术依据与待验证事项

已核对的 Operit 主仓接口：

- [ToolPkg 格式](https://github.com/AAswordman/Operit/blob/main/docs/TOOLPKG_FORMAT_GUIDE.md)：多个子包、UI、环境配置、目录选择授权和 workflow_templates。
- [工作流 API](https://github.com/AAswordman/Operit/blob/main/docs/doc-src/package-dev/workflow.md)：创建、读取、局部更新和触发。
- [聊天 API](https://github.com/AAswordman/Operit/blob/main/docs/doc-src/package-dev/chat.md)：读取列表、绑定已有 ID、原聊天发送。

主仓文档不等于用户 APK 能力。实际版本、设置 UI、私有存储／目录授权接口、异步工作流触发、后台任务寿命和 MAIN 原聊天发送必须各自验证。文件权限仍由 Android 用户授予，连接导入不扩大电脑管理页的访问范围。
