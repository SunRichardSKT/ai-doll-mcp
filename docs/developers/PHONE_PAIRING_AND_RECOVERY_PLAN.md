# 免电脑配对、连接恢复与手机历史补传计划

2026-10-23。状态：**2.25.0 本地候选已整合，待目标环境验收**。基线为软件／Operit 工具包 2.24.1、固件 2.12.1；候选目标为软件／Operit 2.25.0、固件 2.13.1。候选先交付本机 `delivery/`，尚未上传 GitHub Release。软件检查与实际结果统一记在 [2.25 候选报告](../reports/RELEASE_2_25.md)，本计划不替代验收证据。

## 1. 目标与范围

让只有安卓手机的用户完成设备配对和日常恢复，尽量不填写 IP、令牌、文件路径或对话 ID。沿用原 Operit 聊天、模型和人设。

| 场景 | 本轮目标 |
| --- | --- |
| 手机与设备在同一家庭网络，无电脑、无服务器 | 从设备热点读取连接信息，或导入连接文件／连接码；日常按已绑定身份恢复地址，将设备断线缓存归档到手机。 |
| 有自己的服务器，无常开电脑 | 手机导入服务器提供的设备专用连接，设备继续直传服务器；家庭 IP 变化不影响手机连接服务器。 |
| 设备或手机重启、DHCP 换地址 | 保留配对、聊天绑定、人设偏好与历史，恢复同一设备；按实际任务状态展示是否继续陪伴。 |
| 更换路由器、SSID 或密码 | 引导用户连接设备热点重新配网，随后更新地址；同一安装身份保留原绑定。 |

本轮继续使用 Wi-Fi 与 HTTP MCP，不引入 BLE、第二个聊天产品、娃娃账号、Termux、Root 或 Shizuku。手机直连限定于网络互通的局域网；在外访问家庭设备使用已有服务器通路，不公开设备管理页。

## 3. 用户操作流程

### 3.1 只有一部安卓手机

1. 新连接在 Operit 首页点击“添加娃娃”；已有连接在“设备与连接”点击“添加娃娃／从热点找回地址”。
2. 按向导到系统 Wi-Fi 设置连接设备热点，回到 Operit 点击“读取热点设备”。复用 `/api/identity`、`/api/setup` 和认证设备状态，保存待核对的配对草稿。
3. 点击“打开热点设置，配置家庭 Wi-Fi”，打开现有设备设置页。用户只填写家庭 SSID 和密码一次；不在插件中另外保存 Wi-Fi 密码。
4. 等设备实际连接后读取家庭 IP、固定名称和安装身份，再提示用户切回家庭 Wi-Fi。原来已经配好网的设备跳过填写步骤。
5. 点击“已切回家庭 Wi-Fi，完成配对”，核对家庭地址和设备身份，成功后提交。选择已有聊天一次，即可开启触摸主动回复；不要求发送测试消息或手填聊天 ID。

设备设置页同时提供手机连接文件、连接码和临时显示的二维码。同一手机优先用热点读取或文件导入；面对另一块屏幕时可拍照，也可从相册识别本手机保存的二维码。**无需在设备、PCB 或外壳贴标签**。保留手填地址作为高级入口。

热点读取失败时，仍可用手机浏览器打开 `192.168.4.1` 下载连接文件。该地址只在连接设备热点时可用，不能写成家庭 IP。系统网络切换由用户确认，向导不承诺静默切换 Wi-Fi。

### 3.2 使用自有服务器

1. 手机打开自己的服务器管理页，完成设备配对和直传配置。
2. 该设备下提供“连接 Operit”：二维码、连接文件、复制连接码三种入口，使用同一份载荷。
3. Operit 核对服务、配对记录和 MCP 能力后保存，绑定原聊天。服务可达但设备离线时，明确区分两个状态。
4. 设备家庭 IP 变化由设备重新联网／上传恢复，手机不搜索服务器背后的家庭 IP。

服务器管理凭据、设备上传配置和 Operit 连接三者保持分离。已有连接 JSON 继续兼容；不把管理链接当作 MCP 地址。

### 3.3 更换家庭网络

同一网络内 DHCP 换地址先自动恢复。更换 SSID 或密码时，页面提供“重新配网”：提示长按 BOOT 打开设备热点，重新填写 Wi-Fi，再读取家庭地址。固定身份用于确认找回的是原设备，不能用于自动获知新 Wi-Fi 密码。

## 4. 连接包、二维码与身份规则

连接包使用有版本的固定 JSON 数据结构，二维码与连接码只是同一结构的编码形式。沿用现有设备／服务器连接类型；新增字段采用可选扩展，旧连接文件导入后增量补齐。

| 数据 | 用途与约束 |
| --- | --- |
| 连接类型 | 明确手机直连或服务器连接，按各自规则验证地址。 |
| 安装 `device_id` | 绑定当前固件安装身份；普通重启不改变，项目标准 USB 烧录每次生成新身份。 |
| 固定 `hostname` | 硬件派生的查找线索，跨 DHCP 和显示名修改保持；不能单独证明原配对仍有效。 |
| 地址提示、显示名称、连接凭据 | 地址用于寻找，名称用于展示；凭据仅在插件本地保存和协议请求中使用。 |
| 服务器持久实例标识与配对 ID | 判断是否仍是原服务／原配对，不使用每次启动变化的运行验证编号。 |

不导入聊天 ID、工作流指令、任意本地路径、模型密钥或物理输出设置。导入先形成候选，核对通过后才替换现有连接；取消或失败保持原配置。

同一身份仅换地址时保留 `storage_key`、聊天绑定、回执、偏好和常开意图。同硬件但安装 ID 变化时停止旧会话，提示重新配对；旧历史独立保留，不静默复用旧令牌或 ACK。

二维码生成、解码均在本机完成，不由模型识别或交第三方网站处理。候选采用本地 jsQR 解码、Nayuki 生成，固定来源、版本、哈希和许可随包保存；不依赖 CDN。Operit 的相机／图片选择器与本地 WebView 连接异步解码，完成后再读回结果，不假设脚本执行接口等待网页 Promise。浏览器解码检查不等于目标 APK 的拍照／选图、权限和 WebView 往返已通过，仍需实测。

不预设系统已注册能直接打开本 ToolPkg 的自定义深链。无需依赖第二部手机；文件和连接码入口必须能单独完成全流程。

## 5. 地址恢复与状态显示

手机连接恢复按以下顺序执行：

1. 快速检查上次核对成功的地址，同时在可用时尝试保存的固定 `.local` 名称；候选去重。
2. 使用只读 HTTP 身份信息核对预期安装 ID，再完成认证 MCP 状态检查；不能仅凭固定名称接受候选，也不向身份不符的旧地址发送配对令牌。
3. 成功后仅更新当前地址和检查时间，保留聊天及历史。失败保留原配置，进入退避等待。
4. 固定名称无法解析时，提供“从设备热点重新获取地址”和“手动更新地址”，不要求重新选择聊天。

一次前台找回目标预算约 8 秒，先显示缓存，再异步检查；目标手机实际耗时仍待测量。候选后台失败使用 2、5、10、30、60 秒退避，成功后重置；停止任务后不再安排重试。共享一个正在进行的恢复任务，页面与后台不同时发起多轮搜索。

现有 ToolPkg 桥未确认暴露 UDP、Android NSD 或 Wi-Fi 网络变更回调。首版不依赖这些接口，不穷举整个子网；前台进入、任务续接及已知连接失败都可触发有界恢复。Android 原生支持 NSD 不等于当前插件可直接使用。若后续确认桥支持，则复用现有已配对 UDP 挑战发现作为增强，不创建另一套身份机制。

页面显示缓存连接及检查／在线／离线状态，配对、身份、凭据和主归档端占用错误给出对应提示。离线时保留上次确认地址和时间，不能把缓存地址说成当前已确认在线。不能仅凭连接失败推断手机一定切到了移动网络或设备已断电。

短暂断线且启动 ID 未变时保留仍有效的排队触摸。设备重启后旧会话结束，清理未发送的旧会话反馈；只有用户原先开启常开时才尝试新建有限会话。重新同步的旧记录仅归档，不因恢复而突然向聊天发送。

## 6. 手机历史补传

### 6.1 同步与主动回复分开

配对完成后首页提供独立的“自动同步记录”设置，默认开启，触摸主动回复仍默认关闭；已有用户的主动选择保持。主动回复关闭后不清历史，也不关闭用户选择的记录同步。“停止后台任务”同时暂停同步和自动续接，恢复时重新开启同步开关。

一个设备只运行一个采集任务，界面检查、实时互动和历史补传共用它。同步任务沿用有限后台任务与续接，不另起重复工作流。手机关机、Operit 被强制停止或 Android 暂停任务时不会继续采集；恢复后只补设备尚保留的缓存。

### 6.2 实时优先，补传分页

复用 `get_touch_events`、`get_event_storage_status`、`set_device_time` 与 `acknowledge_events`：

- 实时通路使用当前启动的 `after/next_cursor`，先读取 `include_persistent:false`。
- 补传通路使用独立的 `storage_epoch/storage_cursor`，每次最多 24 条；两条通路进入同一个归档器。
- 积压较多时交替处理实时页和补传小页，不把实时读取排到所有补传之后。固件目前对 Flash 与 RAM 共用 24 条响应预算，因此不能只把原调用改成 `include_persistent:true`。
- 同一事件统一按设备安装身份、事件本身的启动 ID 与 `seq` 去重；RAM 与 Flash 重叠只保存一次。`storage_id` 是补传位置，不能代替压力动作或聊天回执 ID。

### 6.3 先持久归档，再确认设备

候选已增加可恢复的批次归档段与提交记录，日历索引和近期索引可从归档段重建，不以当前 2000 条索引作为唯一去重依据。

顺序固定为：接收一页 → 按稳定事件 ID 归档 → 写入完成并读回校验 → 提交该页同步状态 → ACK → 记录确认结果。只确认本页所有条目都已可靠保存的游标，不确认整个设备最新序号。

ACK 使用本次响应外层的当前 `boot_id`、本页 `storage_epoch/storage_cursor`；不能拿某条旧事件的启动 ID 确认。写失败不 ACK；ACK 丢失允许重读和去重，不重复生成聊天回复。读取与 ACK 之间发生设备重启或存储 epoch 改变时重新读取状态，不自动重发过期 ACK。

候选使用可校验归档段和提交记录恢复半写入，无法确定提交时不释放设备副本；不依赖文件替换作为事务保证。普通 `Files.write` 返回成功不能直接当数据库事务或物理断电保证。文件故障替身、目标 APK 杀进程恢复与手机突然断电分别验收。

### 6.4 时间与来源

沿用电脑归档规则：可信设备时钟优先；同一启动有时间锚点时估算；从未建立锚点的旧启动事件保持时间未知，进入单独可查询的“时间未确认”记录。按事件实际时间归档，不按收到补传的日期塞进今天；手机校时不改写旧事件。

保留发生时部位、数值、单位、质量、模拟来源及原事件身份。补传历史统一只归档；当前会话的新触摸才按现有新鲜度和队列规则进入回应。释放更新动作时长，不补发主要反馈。

### 6.5 主归档端归属

候选固件增加轻量、有限期限的归档租约，并同步适配手机、电脑采集器和设备直传。TTL 为 90 秒、每 30 秒续租；租约绑定本次启动，不写成永久设备锁。实际时序与多端切换仍需实板验收。

同一时刻仅一个主归档端可确认 Flash 缓存；只读状态与历史查询继续可用。设备不再以一个全局“曾经返回过的游标”作为全部消费者的确认依据，而是核对租约身份和该持有者实际收到的游标。占用时显示归档端类型及租约剩余时间，显式停止／释放或过期后才能切换，不自动抢占。

设备直传开启时手机继续引导使用服务器模式。旧客户端 ACK 遇到有效租约必须明确拒绝，不能删除手机未保存的记录；相关错误进入可见状态。

旧固件无租约时，手机仅提供“兼容复制归档，不自动 ACK”：只能复制当前可读的最多 24 条持久记录，缓存不清理，因此不保证读取其后的完整积压，也不保证跨端独占。完整分页与 ACK 需要固件和主采集端均通过能力检查，不能靠手机版本或页面提示假定已有归属。

固件增加小型归档协调协议及设置页的本地二维码资源，保持现有分区、OTA、缓存容量、校准和电气参数。构建与剩余槽位以本次编译输出为准，不沿用基线的 36.4 KiB 余量；二维码解码库仅放手机端。不得挤掉历史或 OTA 分区容纳功能。

锁屏测试至少记录当前目标手机的 Android、Operit 版本和省电设置；有第二台不同系统手机时另测，不由单机结果推断全机型支持。软件故障替身、真实 CH0 与原聊天反馈分开记录。只有实际安装的通道可纳入实体验收。

## 10. 迁移、交付与边界

- 保留插件身份 `org.ai_doll.companion`、现有 `storage_key`、旧历史、聊天和回执；采用增量迁移，归档校验通过前不移除旧文件。未知旧时间不补造。
- 同版交付手机工具包、服务器包、电脑采集适配和必要固件；升级前做能力发现，不能只更新手机就宣称设备已有租约。新固件沿用标准更新流程，不自动全片擦除或改变校准。本轮未烧录用户设备。
- Linux 候选升级从新包解压目录运行包内安装器，并复用原目录、项目和持久卷；尚未发布时不运行已安装入口联网升级到 2.25。电脑／手机分别保留数据目录，不清数据重新安装。
- 更新 [Operit 免电脑指南](../integrations/OPERIT_NO_PC.md)、[Operit 设置指南](../integrations/OPERIT_SETUP.md)、[配网与恢复](../daily/WIFI_CONNECTION.md)、[离线记录](../daily/OFFLINE_RECORDS.md)和 [AI 执行指南](../ai/AI_GUIDE.md)。AI 指南明确身份变化、同步／回应分离、旧记录不唤醒、未知时间与实际验收边界。

## 2.13.1临时热点与管理访问

配对窗口最长600秒；新配置的STA首次连通后最多再保留90秒，重复连接不延长窗口。已有STA连接时手动打开保留完整窗口及STA链路；无网只退避重连，不自行开AP。BOOT、USB `setup_mode` 或已授权LAN管理可开启；热点客户端不能通过HTTP续窗。关闭AP不清除Wi-Fi、身份、通道、校准或归档租约。

设备状态增加`setup_window_supported`、`setup_remaining_sec`、`setup_password_required`（已保存的下次热点密码状态）。`POST /api/hotspot`仅为设置页管理接口，要求现有管理鉴权、同源检查和`X-Setup-Token`，action为open、close或password；password为空或8～63字节，下次开热点生效。USB维护示例：`{"cmd":"setup_mode","password":"","enabled":true}`重设热点为无密码并开启临时窗口；`enabled:false`仅关闭。没有增加模型可用工具。

`/api/identity`公开最少身份信息；`/api/setup`及状态、配置API要求物理热点窗口、已配对令牌，或已开启的网页登录认证。静态页面不含凭据，允许加载；新浏览器裸LAN地址不会导出令牌。已配对客户端给设置链接附加`#setup_token=...`，网页读入sessionStorage后清除片段，不放入查询参数或日志。若开启网页登录仍须登录；物理热点窗口提供登录恢复，独立热点密码仍生效。

服务器直传与OTA沿用原鉴权和LAN限制。网页开关热点不应中断在线STA或上传，实际无线、手机切网和OTA仍需目标设备验收。旧固件保持原行为，需要升级镜像才获得限时策略。
