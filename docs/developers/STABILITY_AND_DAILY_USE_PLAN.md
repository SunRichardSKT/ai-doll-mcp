# AI Doll 连接稳定性与日常使用优化计划书

编制日期：2026-10-19。状态：代码与2.21.0交付完成（2026-10-20），目标环境验收待完成。当前进度、实测证据与待验收项见[2.21 更新记录](../reports/RELEASE_2_21.md)。本文件保留原设计和验收目标。

本计划覆盖 Operit 地址变更、烧录命名、重启恢复、真实硬件默认体验及代码精简。实施阶段按实际文件、进程和设备返回重新确认状态，本文中的诊断观察不代替届时的检查。

## 一、目标与交付标准

让已安装主板与传感器的用户，完成一次配对后即可日常使用。地址变化有明确的修改入口，重启后可以恢复已配置的服务，连接失败能够显示具体故障位置。继续使用用户原聊天、模型、人设和上下文。

| 目标 | 完成后的用户体验 |
| --- | --- |
| Operit 地址变化可处理 | 修改电脑 IP 即可恢复，无需重新导入工具包或绑定聊天 |
| 设备名称容易辨认 | 烧录时可选随机名称或自定义名称，完成后显示实际回读结果 |
| 重启后连接可恢复 | 日常启动及已开启的登录启动恢复完整服务，故障时有一键修复入口 |
| 默认面向实体使用 | 新安装默认 CH0 真实采样与日常模式，模拟测试放入开发者选项 |
| 代码便于维护 | 合并重复启动和错误处理，清理确认无用的旧入口，保留现有工具兼容 |

交付以相关检查、实际设备和目标聊天证据共同验收。程序能启动、SDK 调用通过或进程存活，分别只能证明对应环节。

## 二、诊断基础与待确认事项

本次前期检查得到以下结果：

1. 电脑采集服务和本地 MCP 正常，设备仍在同步，采集器未报告错误。
2. 当前 Windows 登录启动未启用；现有登录入口即使启用，也仅启动采集器，没有恢复 Secure 隧道和 Operit 服务。
3. Secure 客户端进程存活，但控制面健康报告出现连续 `network_error`，没有近期成功连接证据。现有启动逻辑主要判断进程是否运行，可能复用失效的运行实例。
4. 电脑已配置出站代理，运行中的隧道健康报告显示直连。代理未应用或启动时保留旧配置是需要验证的线索，尚不能仅凭此确认唯一原因。
5. 两个远程状态工具实际返回 OpenAI 隧道网关 429，未到达本机工具执行阶段。这个结果不能单独证明 API 额度耗尽，也不能归因于传感器硬件。

实施前保存必要的本机诊断，分别核对设备、采集器、本地 MCP、隧道控制面及目标聊天。公开报告只总结故障与结果，不附个人配置和历史。

## 三、工作项与具体方案

### 1. Operit 地址变更与设备 IP 展示

本轮采用手动修改电脑 IP 的方案，不要求用户配置路由器固定地址，也不增加手机自动发现协议。

**手机操作：** Operit 设置增加“电脑 IP”输入框及“检查并保存”按钮。修改时只替换电脑地址，保留原连接端口和路径；继续使用原聊天绑定、反馈偏好与去重记录。更新成功后，后续工作流从当前配置读取地址，不能继续使用创建工作流时写死的旧地址。

**电脑操作：** 管理中心列出当前可用的局域网地址，并显示 Operit 服务实际使用的地址。服务绑定旧地址时，提示用户选择当前地址并保存启动；导出的连接信息随之更新。电脑与手机均明确将该字段称为“电脑 IP”。

**设备设置：** 单独显示 ESP32 当前局域网 IP、网络连接状态及可点击的设置链接。尚未取得有效 IP 时显示“未连接”，不能显示缓存地址并宣称当前可用。USB 连接下也从设备实际状态取得 Wi-Fi IP。热点地址 `192.168.4.1` 注明“连接娃娃热点时使用”，电脑管理页的 `127.0.0.1` 注明仅该电脑可用。

**变更中的互动：** 更换连接前结束旧地址的等待任务；保留待确认投递状态，连接成功后按原聊天恢复新任务。失败时保留原配置并给出具体原因，不清空发送记录或自动重绑聊天。

**验收：** 改变电脑地址后，用户通过上述入口恢复连接；原聊天绑定和历史保留，工作流确实使用新地址，同一触摸不重复反馈。设备离线、电脑不可达和填写错误地址分别显示对应状态。

### 2. 烧录随机名称与自定义名称

烧录页面提供“随机名称”和“自定义名称”两种选项；命令行同步提供自定义名称参数，未填写时沿用现有随机命名。

自定义名称用于设备显示和配网热点，允许中文，按热点名称的 UTF-8 长度限制校验。去除首尾空白，不接受空白名称或控制字符。选择随机模式时清除旧自定义名称，恢复默认显示方式。

设备显示名与内部配对编号分离。每次 USB 烧录仍生成新的内部编号与烧录记录；自定义名称不替代配对身份，也不作为发现设备的唯一依据。状态和配网接口分别返回显示名、实际热点名和内部编号。

标准烧录继续保留设置与校准；恢复出厂使用原来的独立流程。新增命名能力随配套固件交付，旧固件不支持时明确提示，不虚报名称修改成功。

**验收：** 分别验证随机名称、中文自定义名称、长度超限、从自定义切回随机，以及断电重启后的保存结果。成功条件包含镜像写入校验、应用启动和名称／编号回读，不能只依据烧录器的写入提示。

### 3. 设备与电脑重启后的 MCP 恢复

统一日常启动和 Windows 登录启动的恢复逻辑，按依赖顺序恢复：采集器 → 本地 MCP → 已配置的 Secure 隧道；已启用的 Operit 服务独立恢复。未配置的通路跳过，一条通路失败不阻断其他通路。

采集器进程入口与完整恢复入口保持职责清楚，避免日常启动、后台入口相互递归。复用现有进程归属记录和单实例机制，不增加第二套守护服务。

具体处理如下：

| 故障位置 | 处理方式 |
| --- | --- |
| Windows 登录时网络尚未准备好 | 先恢复可用的本地服务，远程连接采用有上限的退避重试 |
| 设备重启或 Wi-Fi IP 变化 | 复用已配对设备发现与身份核对，更新验证通过的新地址 |
| USB 串口变化 | 在没有明确指定串口时重新识别原设备；身份核对通过才保存新串口 |
| 隧道存活但连接失败 | 结合近期控制面成功记录、错误类别与本地 MCP 状态判断，不能仅看进程 |
| 系统代理变化或未应用 | 按官方客户端支持方式配置出站代理；核对实际运行路由，必要时重启本项目隧道 |
| 网关 429 或临时服务异常 | 展示实际错误并退避，不通过不断重启、重置地址或重新配对处理 |
| 凭据失效或权限错误 | 提示检查对应配置，避免无限重试或将其误报为设备离线 |

管理中心分别展示“设备采集”“本地 MCP”“ChatGPT 隧道”和“Operit”状态。增加“修复连接”按钮，执行诊断、启动缺失环节及恢复允许重试的连接，结束后显示仍未通过的环节。

登录启动由用户开启，恢复既有服务配置；恢复服务不自动开启触摸主动回应，不延长已到期互动会话，也不重发结果不明确的控制命令。

**验收：** 覆盖设备重启、电脑服务完整退出后重新启动、实际 Windows 重新登录、延迟联网、代理变化及短时断网。核对历史数量和校准配置，再在目标普通 Chat 实际调用两个状态工具，取得新的 `verification.call_id` 并与服务记录匹配。尚未取得的实测证据单独列为待验收。

参考：[官方 Secure MCP Tunnel 说明](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)。

### 4. 真实硬件默认体验与开发者选项

新安装面向已组装主板与传感器，默认启用 CH0 实体压力输入及日常采样。其他通道由用户按实际接入情况启用，不据 CH0 的验证推断全部通道已安装。物理输出仍关闭。

已有安装保留保存的通道、工作模式、名称、阈值与校准。需要从手动模式切换时，提供明确的日常模式入口，不在升级过程中静默覆盖用户设置。

普通页面以连接、部位、采样状态和互动设置为主。模拟按压、模拟输入类型及原始诊断入口集中到“开发者选项”；离线时不自动切成模拟数据。

| 调试窗口 | 内容 |
| --- | --- |
| 传感器读数 | 通道、原始读数、阈值、有效性、数据来源与更新时间 |
| 事件记录 | 按压、释放、时长、部位及真实／模拟标记 |
| 当前配置 | 通道驱动、采样模式、校准和重启恢复设置 |
| 连接诊断 | 设备连接、同步状态、本地 MCP、隧道路由与最近错误 |

优先复用已有只读接口。窗口展开后刷新，关闭或离开页面后停止；显示有界数量的记录。查看事件不消费缓存，不修改历史游标、校准或采样状态。

**验收：** 新安装默认读真实 CH0；已有配置升级后保持；普通页面不出现模拟测试按钮；开发者窗口能定位真实读数、事件和连接问题，关闭后停止刷新。模拟结果始终标明来源。

### 5. 代码与流程精简

精简与功能实施同步进行，优先处理本轮涉及的模块，不开展无边界的目录重构。

1. 日常启动和登录启动调用同一套服务恢复逻辑，合并重复的启停与检查步骤。
2. 底层保留可定位的错误类型，由统一出口转成用户提示；清理重复捕获、吞错和多层通用兜底。
3. 配置在输入边界进行必要校验，内部复用已确认结果，减少同一路径重复解析和验证。
4. 清理经过引用检查确认无用的旧原型入口，已有公开工具名称和外部启动路径保持兼容。
5. 调试页面复用现有状态与事件数据，避免另存一份诊断数据库或再建一套连接管理器。

身份核对、历史与校准保留、进程归属、事件去重及禁止重复发送写入／输出命令属于必要行为，精简时继续覆盖这些边界。

**验收：** 相关回归检查通过；公开工具调用兼容；同一操作只有清晰的执行路径；失败能定位到实际环节。交付记录说明合并及删除的入口，不以删除行数作为完成指标。

## 六、交付物与升级安排

- 可安装的 Windows 完整包、Operit 单一工具包及配套固件；涉及共享代码时同步检查 Linux 小型包。
- 更新后的首次安装、Operit 地址修改、烧录命名、日常模式和故障排查指南。
- 分阶段验证记录，包含已通过项目、证据来源及尚未完成的目标环境测试。
- 固件与完整包校验清单，公共内容按允许列表打包。

升级采用增量配置迁移，不删除个人历史、配对、校准、聊天绑定和投递记录。新增固件先构建并校验，再安排实际烧录与设备回读；本计划书本身不执行设备升级。

发布前验证固件清单、完整交付包、文档链接和本机数据排除。验收通过后更新 GitHub 源码、Releases 与下载说明，明确各包实际包含的版本，避免仅上传源码而让用户误以为旧安装包已更新。

## 七、本轮范围

本轮完成上述五项并给出明确的升级和恢复路径。普通 Chat 空闲主动唤醒、Operit 全机型锁屏常驻、未安装通道的硬件认证及 PCB 改版不纳入本轮承诺。
