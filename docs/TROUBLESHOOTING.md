# 故障排查

按当前现象找对应行，每次修复后再检查一次；不要先全片擦除或删除历史。

## 启动与设备网络

| 现象 | 先检查 | 通过的标志 |
| --- | --- | --- |
| 提示需要 Python | 使用完整交付 ZIP，完整解压并保留 `python/`、`tools/` | 双击打开管理中心 |
| 管理中心打不开 | 目录可写；端口 8769 没被别的程序占用 | `127.0.0.1:8769` 可打开 |
| 灯慢闪 | 等待最多 60 秒；确认 2.4 GHz Wi-Fi | 常亮，设备显示已联网；设置热点保留 |
| 配网成功后找不到设置页 | 手机重新连接娃娃热点，输入 http://192.168.4.1/ | 同一固定地址能打开 |
| 再次烧录后旧设备名失效 | 每次 USB 烧录按设计换新名称，用 USB 重新识别/配对 | 实际新 ID 与烧录报告一致 |
| 烧录页面提示失败 | 展开本次日志，查看独立目录中的 result.json；按错误处理后手动重试 | 写入、启动与编号均验证成功 |
| 没有弹出配网页 | 连接娃娃热点后手动访问 `192.168.4.1` | 出现设备设置页 |
| 不知道 IP / IP 改了 | 使用“查找已配对设备”，首次可 USB 一次识别 | 重新验证实际设备 ID |
| Wi-Fi 连上但电脑无法访问 | 同一可互通网络，检查访客网 / AP 隔离与 VPN | 配对验证通过、同步时间更新 |
| 已联网但显示同步异常 | 看当前连接方式；旧 USB 失效可点击查找已配对设备，Wi-Fi 地址变更可自动恢复 | 显示实际 Wi-Fi 地址，最近同步持续更新 |
| 串口拒绝访问 | 关闭占用同一串口的监视器或烧录网页 | 仅一个采集程序连接串口 |
| 设备连接忙 | 等当前请求结束再检查；控制命令不会自动补发 | 状态刷新成功 |

按钮、配网与登录说明见 [日常指南](daily/USER_GUIDE.md)和 [登录保护](daily/RUNTIME_AND_LOGIN.md)。

## MCP 与原聊天

| 现象 | 如何处理 |
| --- | --- |
| AI 说没有工具 | 确认正确连接已启用到当前聊天；刷新工具列表；不能只上传说明 ZIP |
| 显示 `SSE stream not offered; use POST` | `/mcp` 是工具接口，不是网页；浏览器访问设备根地址，MCP 客户端使用 POST |
| 401 / 403 | 设备接口查配对令牌；Secure 查运行密钥权限和账号关联；不要互换凭据 |
| 隧道进程在，但 Chat 不通 | 用管理中心实际检查；再按 [原 Chat 测试](integrations/CHAT_MCP.md)调用两个状态工具 |
| 第一次查询通过，重启后没有工具 | 确认选的是同一个插件 / 隧道，重新检查服务；旧调用编号不算新验证 |
| 没有按压反馈 | 先查新事件是否归档，再查当前会话、期限、来源和安静时段；普通状态不会主动回复 |
| 历史可读但设备状态失败 | 历史来自本机数据库；修复采集连接后再读实时状态 |
| Sakura SDK 可用，普通 Chat 添加失败 | 此问题尚未解决；当前已验证入口为 [Secure](integrations/SECURE_MCP.md) |

## 直传服务器

| 现象 | 如何处理 |
| --- | --- |
| 域名未解析 | 修复 A / AAAA，等待解析生效，再运行安装入口 |
| HTTPS 验证超时 | 查 DNS、云安全组 / 防火墙 80、443 和 `sudo ai-doll-server logs`；修复后执行 `start` |
| 管理页正常，娃娃离线 | 手机打开设备页，检查 Wi-Fi、直传开关和保存的配置 |
| 电脑 MCP 不再收记录 | 直传开启时采集器停止消费缓存；切回电脑模式先关闭设备直传 |

[远程安装](integrations/REMOTE_SERVER_SETUP.md)提供重试和管理命令；停服务或更新不应删除数据卷。

## 仍然不能解决

记录错误原文、操作时间、当前软件版本、使用的连接方式，以及最新实际状态。可在管理中心导出诊断；不要把旧在线截图作为当前证据。

硬件真实读数、OTA 和缓存问题分别查看 [通道](daily/SENSOR_CHANNELS.md)、[无线升级](daily/OTA_UPDATE.md)、[离线记录](daily/OFFLINE_RECORDS.md)。
