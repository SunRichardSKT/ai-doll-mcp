# 离线记录与补传

设备保留最多 **256 条待补传事件**，电脑将事件写入本地历史后才确认清除。按下和释放各占一条；温度采样和震动命令也分别占用记录。它是有限的断线缓冲，不是无限期的独立日志库。

## 日常操作

1. 按 [无线连接指南](WIFI_CONNECTION.md) 配对，在同一局域网启动电脑服务。使用 USB 采集也可以。
2. 打开 <http://127.0.0.1:8768/companion>，查看“离线记录状态”。正常补传完毕后，“待补传”应回到 0；“容量覆盖”是累计数量，不会自动回到 0。
3. 电脑休眠、服务关闭或网络断开时，独立供电的设备继续缓存已产生的事件。真实压力输入仍需已接好传感器并启用日常模式；裸板不会自动生成真实压力。
4. 电脑服务恢复后自动分页补传、去重和确认。无需 AI 手动调用确认工具。普通模式只归档；旧事件补传不会触发过时回复，也不会重新执行震动。
5. 查询日期时默认只显示有可信日期的记录。没有时间依据的记录在“全部日期”中显示“时间未知”。AI 不应把这些记录称为“今天发生”。

可以让 AI 调用只读工具 `get_event_storage_status`，检查容量、待补传数量、累计覆盖与损坏数量、本次启动写入失败数、时钟校准状态及文件系统空间。当前电脑 MCP 共 45 个工具；设备 HTTP MCP 共 26 个工具。升级后重新连接 AI 客户端刷新工具列表。

## 时间如何确定

设备联网并不代表已经校时。电脑采集服务会提供 UTC 时间；新启动首次采集立即校时，之后定期检查偏差，不依赖外网 NTP。

| 时间质量 | 含义 | 页面表现 |
|---|---|---|
| `device_clock` | 事件产生前，本次启动已由电脑校时 | 日期 + 设备时钟 |
| `estimated_from_boot_anchor` | 已知该次启动的时间锚点，使用运行时长估算 | 日期 + 估计时间 |
| `legacy_estimate` | 按接收时间估算的记录，不等同于精确发生时间 | 日期 + 估计时间 |
| `unknown` | 设备在电脑从未见过的一次启动中产生事件，未校时便重启 | 时间未知；不进入按日统计 |

时间取决于电脑时钟是否正确。未知时间不能仅凭“刚刚收到补传”恢复为实际发生时间。来自其他启动，或当前启动中已超过 5 秒的事件，标记为 `offline_replay`，仅进入历史；当前启动的及时事件仍能进入正常互动推送。补传不会延长当前互动会话的空闲计时。

开始互动时保存设备启动标识和最新事件序号。当前启动的新事件若因校时时延比会话开始时间早不到 2 秒，可依据序号边界归入会话，并标记 `session_time_quality=sequence_boundary`；原发生时间不修改。旧序号、旧启动和更大时间偏差不能使用此判断。

## 容量、异常与可靠性

- 缓存满后覆盖最早的事件并增加 `lost_records`。256 条事件最多对应 128 次完整按下/释放，混合传感器记录会共同使用容量。
- 文件使用 CRC 校验和临时文件提交。记录按存储周期和序号区分，电脑数据库提交成功后才发确认；确认丢失会再次读取，但不会重复归档。
- 现有 4 MB 分区表不变；文件系统区约 1.4 MB。每条文件最多 1536 bytes，256 条正文上限 384 KiB，实际占用还包含文件系统元数据。
- 首次使用仅在整个文件系统分区为空白时格式化。已有数据区挂载失败不会自动格式化，而会报告缓存不可用；此时 RAM 记录仍受重启和容量限制。
- 检测到损坏文件或启动时遗留的未提交临时文件，会丢弃该文件并增加损坏计数。写入失败会报告，不能将其视为已成功持久保存。
- USB 状态/事件读取超时可重连后再读一次；其他控制命令不自动重发。网络断开时仍可在电脑侧结束互动会话。
- 每条事件都会写 Flash。频繁温度采样会更快占满缓存并增加写入量，请按实际需求设置采样间隔，不把此实现当作高频数据记录器。

设备的 `acknowledge_events` 与 `set_device_time` 是采集器内部工具。不要让其他程序抢先确认尚未写入长期历史的记录。多台电脑同时确认同一设备会影响各自收到的历史，当前应保持一个主采集器。

## 测试与实际边界

当前裸开发板验收覆盖软件重启后的补传、256 条容量上限、270 条模拟事件覆盖最早 14 条、未知时间标记、重复读取去重以及原通道配置恢复。测试历史明确标记为模拟数据。

尚未验证写文件过程中物理拔电、人为损坏 Flash、完整分区耗尽、真实压力传感器或震动驱动。软件重启测试不等同于任意时刻断电测试。底层文件系统的设计背景见 [LittleFS 官方说明](https://github.com/littlefs-project/littlefs/blob/master/DESIGN.md)。

逻辑测试：`python -m unittest discover -s tools -p "test_offline_archive.py"`。实机测试 `python tools/test_offline_device.py COM3` 必须先停止采集服务；它会在现有历史库写入模拟数据、重启设备并验证容量覆盖，不适合正在进行用户互动时运行。

历史导出、删除、统计和可选保留期限见 [历史管理指南](HISTORY_MANAGEMENT.md)。
