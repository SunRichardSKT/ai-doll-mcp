# 代码完善与验收计划

目标：八路 FSR402 可以校准和设置阈值，首次配网后无线使用，用户与传感器互动时由所选 AI 在支持的环境中反馈，MCP 与文档提供统一接入。

| 要求 | 当前状态 | 下一项验收 |
|---|---|---|
| 八路独立阈值、简易校准、推荐值 | 代码/原生算法/裸板门控通过；页面和 MCP 可逐通道操作 | 接好八路 FSR402，验证装棉后的静置/轻按/强按和释放 |
| 首次配网、60 秒恢复、BOOT 重配、无线传输 | 配网专项通过；当前镜像 Wi-Fi 历史和会话链路通过，USB 不传数据 | 实际首次到手安装、电池独立供电与路由器环境 |
| 普通聊天→传感器互动→AI 反馈 | Secure 已通过普通 Chat 状态、今天历史和 60 秒模拟按压文字反馈；会话及调用编号与本机匹配 | 实物触摸、自定义人设及支持宿主的空闲唤醒另行验收 |
| 更新 MCP | 当前电脑 45 工具、设备 26 工具；官方 SDK 与事件协议通过 | 在用户实际 AI 客户端安装、调用并核对事件能力 |
| 当前安装/教程 | 首次安装、使用、无线、校准和完整工具目录已重写；补充原聊天接入流程 | 随实际客户端接入验收更新当前能力，不能把诊断演示当作聊天体验 |
| 扩展压力/温度/震动 | 模拟量和数字温度配置、地址绑定、故障处理与软件测试完成 | 实物探头/电机验收，按需要改进 85℃有效性判定 |
| Operit / OpenClaw / 自定义前端 | 官方接口评估、包模板、限时事件转发及本机协议测试完成 | 本轮按用户要求不实际验收这两个平台；有环境后核对原聊天路由与真实送达 |

普通 Chat 通过 Secure 实际发现 13 个工具，并完成状态、历史及限时模拟反馈；Cloudflare 两工具备用连接保留。HTTP 接口复用现有采集器，status/history/interaction 分别为 2/9/13 个工具。SDK、目标 Chat 文本反馈和本机数据库证据分别记录。

Bridge 2.13.0 已实现持久私密地址、只读 history 配置、后台采集/离线历史、服务器期限、聊天归属校验、Sakura 官方客户端校验与专用隧道配置获取、进程启动/停止/状态/退避重试和地址重置。无娃娃账号、密码或默认 OAuth 登录。统一入口 `install_chat_mcp.ps1` 安装本机服务与远程依赖，见 [操作指南](REMOTE_MCP.md)。

Sakura 公网 HTTPS 和工具发现通过 SDK，但普通 Chat 添加失败原因未确定。Secure 为当前已通过目标 Chat 模拟反馈的推荐入口，Windows 官方客户端经过下载校验，独立运行目录支持启动、停止、状态及回环地址重置。首次创建隧道、运行密钥并在 ChatGPT 添加连接，之后双击启动。用户继续使用原 AI 与上下文；公共包只有模板和代码。Claude 通用 URL、固定 Cloudflare 域名及主动事件分别安排后续验收。

保留现有主板、74HC4051、SuperMini、电阻电容和手焊封装。没有传感器时维持手动模式，不开启浮空采样；输出始终需要板外驱动确认且重启不恢复。任意官方空闲聊天的主动唤醒不能由普通 MCP 工具单独保证。

本轮分阶段结果见 [MCP 2.13 验收](MCP_ACCEPTANCE_2_13.md)，既有基础结果见 [设备报告](DEVICE_LAB_TEST_REPORT.md)。普通 Chat 的模拟反馈已通过；全新电脑首次配对、宿主空闲唤醒、自建应用真实模型接入和实物校准属于后续阶段。Sakura 的普通 Chat 问题保持未解决记录。
