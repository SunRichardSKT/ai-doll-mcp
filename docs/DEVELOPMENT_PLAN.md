|---|---|---|
| 八路独立阈值、简易校准、推荐值 | 代码/原生算法/裸板门控通过；页面和 MCP 可逐通道操作 | 接好八路 FSR402，验证装棉后的静置/轻按/强按和释放 |
| 首次配网、60 秒恢复、BOOT 重配、无线传输 | 配网专项通过；当前镜像 Wi-Fi 历史和会话链路通过，USB 不传数据 | 实际首次到手安装、电池独立供电与路由器环境 |
| 普通聊天→传感器互动→AI 反馈 | 当前工作任务的 Wi-Fi 模拟按压→MCP→同对话 AI 反馈通过；原聊天队列与取消专项通过 | 普通 Chat 两状态工具已通过；下一步验收互动工具和模拟按压反馈，随后检验支持宿主的空闲唤醒及原 API 模型 |

普通 Chat 的两个状态工具已实际通过，临时转发已关闭。新增本机 HTTP 接口复用现有工具：默认两个只读状态工具，私有互动配置提供 13 个工具。已通过本机 SDK、Wi-Fi 模拟开始/释放、会话结束及并发等待专项；尚未在普通 Chat 验收按压反馈。

部署目标：本机 Agent 使用 STDIO 无需公网；在线客户端通过自托管 HTTPS 或低成本隧道连接。统一安装入口已有依赖安装、首次令牌配对、已配对地址恢复、MCP 配置、服务启动和真实连接验证。本轮在已有环境实测通过；全新 Windows 安装仍需独立验收。SakuraFrp 说明已按官方资料整理，但自动隧道配置/启动、完整远程认证服务及该提供者实测尚未完成。

下一步完成远程互动认证、提供者配置及目标普通 Chat 的限时互动。用户继续使用原 AI、人设和上下文；已有 API 应用复用原后端模型。普通触摸安静归档，结束/切换聊天后禁止迟到投递。

保留现有主板、74HC4051、SuperMini、电阻电容和手焊封装。没有传感器时维持手动模式，不开启浮空采样；输出始终需要板外驱动确认且重启不恢复。任意官方空闲聊天的主动唤醒不能由普通 MCP 工具单独保证。

验收证据及具体限制见 [测试报告](DEVICE_LAB_TEST_REPORT.md)。总体工作仍未完成，尤其是普通 Chat 按压反馈、远程一键部署、宿主空闲唤醒、自建应用真实模型接入和实物校准。
